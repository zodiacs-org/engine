# Station and lunation search for 2.1.0

**Decision requested.** Add two synchronous searches to `@zodiacs/engine/calc`, `searchStations` and `searchLunations`. The prototype answers every previously unsupported L4 event on the shipped DE440 pack. Its largest station discrepancy is just over 16 seconds, against 49,110 seconds allowed for that event. Its largest lunar discrepancy is about 2 milliseconds, against 2 seconds allowed. Acceptance for a candidate requires a decision on the size caps and on how to describe the explicitly selected or fallback astronomy-engine source. That source misses 19 of the 40 lunation tolerances. [Measurements](../evidence/station-lunation-search/residuals.csv)

## Public contract

A longitude crossing takes a body and a target longitude in the requested zodiac. A station takes a planet, and a lunation takes an angle between two bodies. Adding kinds to the existing `events()` request could express all three, but widening its existing result type would make TypeScript consumers narrow before reading `retrograde`. Overloads could preserve common calls but would also change the callable type used by wrappers and utility types. Two named exports preserve the 2.0.0 function, its accepted options, return shape and declarations. The bare crossing entry stays ephemeris-free. The new functions follow the typed-refusal and receipt conventions of `./calc`. The exact declarations are in the [API report](../../api/calc.api.md).

```ts
import { searchStations, searchLunations } from "@zodiacs/engine/calc";

const window = { from: "2024-04-01", to: "2024-05-01" };
const turns = searchStations({ ...window, body: "Mercury", maxSamples: 250 });
const quarters = searchLunations({ ...window, phaseDegrees: 90 });
if (turns.status === "ok") {
  for (const turn of turns.events) {
    console.log(turn.at, turn.direction, turn.bounds.timing, turn.ephemeris, turn.flags);
  }
}
```

| Request or result | Meaning |
| --- | --- |
| `body` | Mercury, Venus, Mars, Jupiter, Saturn, Uranus, Neptune or Pluto. On the pack, Mars through Pluto are planetary-system barycentres. |
| `phaseDegrees` | Exactly 0 (new), 90 (first quarter), 180 (full) or 270 (last quarter). One phase per call. |
| `from`, `to` | Existing `CalcTime` inputs, including UTC dates and ISO strings, and Julian dates with scale `tt`, `utc` or `ut1`. Resolve and round each endpoint to the nearest TT millisecond. The interval is open on the left and closed on the right. |
| `maxSamples` | Positive safe integer or `Infinity`. The default is unlimited. One sample is one evaluation of signed speed or phase offset. Every refinement and both confirmation probes count. Source selection, clock conversion and construction of result metadata have fixed additional work per event. |
| Successful search | `status: "ok"`, ordered `events`, `samples`, `ephemeris`, `flags`, and a calc receipt recording normalized endpoints, selection, finite budget if supplied, conventions, engine and source version. Empty and zero-duration searches carry the source label too. |
| Each event | `at` (calendar label at millisecond precision), `jdTt`, `jdUt1`, ephemeris name and version, flags, clock bands, numerical bracket in seconds, angular allowance in arcseconds and estimated TT timing bound in seconds. A station also gives its body, outgoing direction and signed longitude curvature. A lunation gives its requested angle and relative longitude speed. |

The frame is the tropical true ecliptic and equinox of date. Both bodies are apparent and geocentric, with the same reduction and clock. A common shift of longitude cancels in a phase. A time-dependent sidereal shift changes a station's speed, so a sidereal station would need its own definition. Unsupported keys, unknown bodies or angles, invalid dates, invalid budgets and reversed rounded endpoints throw `RangeError`. Pinned ΔT gives `unsupported-combination`. Endpoints outside `CALC_SPAN` in either TT or UT1 give `out-of-range`. A spent budget gives `sample-budget`, including the limit and the count actually used. The whole window may be retried with a larger limit. A zero-length interval succeeds with zero samples.

**Source and clock.** Select the default source once and hold it for the entire search, including derivative probes. The shipped pack spans 1790 to 2210 and covers the calc span from the start of 1800 to the start of 2200, including the two-hour station stencil at either edge. A failed pack open yields astronomy-engine and `de440-unavailable` on the search and every event. Explicitly choosing astronomy-engine yields its name and version with no fallback flag. The wider engine also defines `outside-de440-span`. With the shipped coverage this case is unreachable inside the calc span. A narrower future pack must check the full padded window before selecting a source. Like `events()`, both searches reject a caller-installed `withEphemeris` scope. [Default source](../de440.md) and [clock conventions](../time.md)

TT is the axis for sampling, bracketing and the physical result. The engine converts each root to UT1 and its calendar label once. Before 1972 that label follows the engine's UT1 convention. After the IERS table it follows the engine's continuous UTC rule. `band.utc` and `band.ut1` are one-sigma clock uncertainties in seconds. They are separate from the physical TT timing estimate. An extrapolated ΔT affecting the UT1 label is flagged. A JavaScript date cannot encode 23:59:60. On a TT root inside a leap second the inherited calendar convention folds its label into the next second. Use `jdTt` for event identity, window chaining and ordering.

## Root and uncertainty calculation

Write `wrap(x) = x - 360 floor((x + 180) / 360)`, in degrees. Sample the window endpoints and each intervening TT day. A daily cell may end early at the requested upper endpoint. Keep the sign-changing bracket and bisect on integer milliseconds until its width is one millisecond. Report its upper endpoint. An exact zero belongs to the cell ending there. Probes one TT hour either side of the result confirm the outgoing sign, including at a window edge. This admits both directions of station and rejects a mere touch. Adjacent windows partition the reported TT grid. [Scalar solver](../../src/calc-event-roots.ts)

**Stations.** For apparent longitude λ(t), let h be one hour expressed in TT days. Estimate v(t) = wrap(λ(t+h) − λ(t−h)) / (2h), in degrees/day. Holding the central solar-disc decision for both samples prevents the reduction's light-deflection step from masquerading as a speed. A change from positive to negative is a station retrograde. Negative to positive gives a station direct. The signed local curvature is a = (v(t+h) − v(t−h)) / (2h), in degrees/day². The centre and flank measurements together reach two hours beyond the candidate. The centred velocity has second-order truncation error in h for smooth longitude. Its hour span follows the independent L4 station definition. It is distinct from the narrower derivative in the position API. [L4 arbiter](../../conformance/arbiters/l4/README.md)

**Lunations.** Set D(t) = wrap(λMoon(t) − λSun(t) − phaseDegrees). Search negative to nonnegative transitions on the increasing phase. The jump at the opposite meridian goes in the other direction, including the longitude wrap at new Moon. Confirm D(t−h) < 0 and D(t+h) > 0. The relative speed r = wrap(D(t+h) − D(t−h)) / (2h) is in degrees/day. This defines first and last quarter by longitude difference. Illumination fraction, topocentric elongation and eclipses are separate quantities.

**Timing.** The bound label `estimated` applies to a local physical resolution, conditional on smooth motion. Take the source's measured directional error for the relevant body, project to longitude to first order by dividing by cos(latitude), and express the result in arcseconds. Use the pack's limb allowance where its reduction can change branch. Sum Moon and Sun allowances for relative longitude. Use at least one arcsecond for the final allowance ε, consistent with the angular resolution of the L4 design. All cases report ε. The source tables are the pack's [directional comparisons](../../src/calc-bounds-de440.ts) and the fallback's [sweep](../../src/calc-bounds.ts).

| Quantity | TT resolution in seconds, including a 0.001 s numerical bracket |
| --- | --- |
| Station | 0.001 + 86400 × √(2 × (ε / 3600) / abs(a)) |
| Lunation | 0.001 + 86400 × (ε / 3600) / abs(r) |

At a station the leading change in longitude is quadratic, Δλ ≈ a Δt² / 2. This explains why a shallow station has a wider timing estimate than a sharp one. At a lunation the phase changes to first order as r Δt. A nonfinite estimate is represented by a null bound. The one-millisecond bracket localizes a root of the sampled function. The wider estimate describes how much time corresponds to the stated angular excursion. It is neither a worst-case bound on perturbing the position derivative nor a statistical confidence interval. Passing or failing L4 is decided exclusively against the vector's own tolerance and exact fields. [Independent tolerance rule](../../conformance/arbiters/l4/build.py)

## Completeness, cost and edge cases

- A daily scan assumes at most one speed reversal per cell for the supported planetary longitudes, and monotone lunar phase with less than half a turn per cell. The step is internal. A caller cannot enlarge it and silently alias a synodic cycle. Opposite-meridian jumps, an exact sample at a boundary, a tangent, zero-duration and multi-event windows are distinct cases.
- The returned order is chronological. A station's direction names the motion following it. A zero plateau with no confirmed reversal yields no event. Numerical noise near an exceptionally flat root or two physical reversals inside a single day could defeat sign sampling. Completeness over the entire four-century span is an empirical claim that still needs a denser sweep.
- The existing crossing solver takes a circular longitude, supports stationary touches of a longitude, accepts caller-selected steps and returns JavaScript dates. Feeding it speed would wrap a linear quantity and inherit its touch policy. The private TT scalar scan handles the two new searches while leaving the public crossing solver and ingress path intact.
- Runtime is proportional to window length in days plus the number of roots times the logarithm of the cell width in milliseconds. The coarse count is known before the first position call. A phase sample reads two positions, a station sample reads the centre and its two flanks. In addition to its samples, a located event reads positions for its angular allowance. Memory grows with the number of returned events. A long synchronous call should use a budget or partition at TT endpoints.
- With an intact pack both searches use its existing apparent-place reduction. With an unavailable pack the numerical algorithm stays the same, but a different longitude trajectory can shift the event. The test for a damaged or missing pack checks the labels on individual events. The fallback's larger errors are visible in the measurements below.

## Independent verification

The released 0.3.0 suite derives L4 expected instants from a separate reduction of NAIF DE440s, cross-checked against Horizons. The engine reads its own shipped, refitted pack or the selected fallback. The adapter uses only public functions and time-unit conversions. It requires exactly one result in each vector's supplied window. Zero, multiple or refused results are errors. Historical engine builds lacking the new functions report unsupported. The adapter never consults the oracle to select a result. [Vectors and provenance](../../conformance/vectors/0.3.0/L4-events.json)

| Source and cases | Passed | Largest absolute time discrepancy, shown signed (computed minus expected) | Tolerance for that case |
| --- | ---: | --- | ---: |
| Shipped DE440, station TT | 30/30 | +16.155007362365723 s, L4-STA-0030 | 49,110 s |
| Shipped DE440, lunation TT | 30/30 | +0.001999590778723359 s, L4-LUN-0028 | 2 s |
| Shipped DE440, lunation UTC | 10/10 | +0.0009999275207519531 s, L4-UTC-0007 (tied) | 3 s |
| Astronomy-engine, station TT | 30/30 | +430.2780179977417 s, L4-STA-0014 | 16,664 s |
| Astronomy-engine, lunation TT | 12/30 | −10.729984283447266 s, L4-LUN-0001 | 3 s |
| Astronomy-engine, lunation UTC | 9/10 | −2.2770004272460938 s, L4-UTC-0019 | 2 s |

All station directions agree on both sources. The 30 station cases cover Mercury, Venus, Mars, Jupiter and Saturn across six start years from 1860 to 2140. Their tolerances range from 6,270 to 50,406 seconds. The 40 lunation tolerances are 2 or 3 seconds and cover only new and full Moon. On the default source the largest fractions of tolerance are 0.0003289555561467262 (station) and 0.0009997953893616796 (lunation). The fallback's largest lunation fraction is 5.29850435256958, L4-LUN-0002. The CSV gives every input selection, expected and computed time, signed residual, tolerance, fraction, direction and verdict for both runs. Decimal strings preserve the measured binary64 subtraction before the harness's display rounding. Millisecond-scale results do not support claims of physical microsecond accuracy. [Per-vector evidence](../evidence/station-lunation-search/residuals.csv)

All 640 vectors ran. With the pack, 639 pass and the pre-existing L3 leap-second case is unsupported. All 140 L4 cases pass. With astronomy-engine, 392 pass, 247 fail and the same L3 case is unsupported. Regression tests exercise the five outer planets' reversals over 2024 and 2025, all four lunar phases against USNO's published April 2024 minutes, TT window partitioning, input validation, source attribution, whole-search budget refusals, and timing formulas. Quarter accuracy at the L4 two-second tolerance and independent outer-planet station accuracy beyond Saturn remain unverified. [Conformance report](../../conformance/RESULTS.md) and [search tests](../../src/calc-event-search.test.ts)

Measure code bytes using the static `./calc` import graph, excluding the one shared base64 pack under the same accounting as the package gate. Unpacked package size includes declarations and metadata. The prototype adds no runtime dependency, data file or entry point. The root isolation and exports smoke test covers leakage from opt-in modules. The owner can accept the measured increases at candidate time, or request a smaller implementation and rerun the measurements. The cap decision must account for the final candidate's CHANGELOG, version and README bytes. [Baseline](../evidence/station-lunation-search/base-size.json), [prototype](../evidence/station-lunation-search/prototype-size.json) and [measurement script](../evidence/station-lunation-search/sizes.mjs)

Before a release candidate:

1. Repeat the complete suite on the supported Node matrix and the pinned conformance runtime. Run the public adapter on the pack and on the explicit fallback. Keep the signed results and review every displaced verdict. Recheck API declarations, exports and byte budgets.
2. Audit completeness by comparing daily and offset subdaily scans over the calc span, especially slow outer stations, records adjacent to pack boundaries and near the solar limb. Cross-check a sample of Uranus, Neptune and Pluto stations and both quarters against an independent reduction. Track missed or duplicate roots separately from the timing differences of matched events.
3. Review timing estimates against the residuals by body, direction, phase, source and clock. Compare derivative half-steps around the shallowest roots. Treat any claim covering other times or a fallback with a different source as a new measurement.
4. Record the accepted public API and the source-specific accuracy results in the candidate CHANGELOG and user guide. Approve the final budgets and use the normal candidate archive-binding workflow. The draft changes built files under the carried 2.0.0 version, so archive-binding checks are expected to flag dist changes until a 2.1.0-rc.1 candidate is cut.

## Reproduce

From the repository root with Node 22.22.2, install the lockfile and build first. For the full raw-kernel tests, set `PRECISION_KERNEL` to the verified `de440.bsp` as in the tier-B CI job. Use a normal Unix build umask of 022 when running the archive-fixture tests.

```sh
npm ci
npm run typecheck
npm run build
npm test
npm run exports:smoke
npm run api:check
node --test conformance/harness/selftest.mjs
node conformance/harness/validate.mjs --expect-total 640
node conformance/harness/run.mjs --adapter "node conformance/adapters/zodiacs-engine.mjs" --out conformance/results/zodiacs-engine.json
node conformance/harness/run.mjs --adapter "node conformance/adapters/zodiacs-engine.mjs --ephemeris astronomy-engine" --out conformance/results/zodiacs-engine-astronomy-engine.json
node conformance/harness/report.mjs
node docs/evidence/station-lunation-search/measure.mjs
node docs/evidence/station-lunation-search/sizes.mjs .
npm run package:contents
```

The harness requires `--out` or `--check`. To verify committed verdicts in place, use `--check` with the same results paths, then `report.mjs --check`. For the size baseline run the same size script against a clean build of `eafc122d70ff21e6555f303f90d69b4fd239d5a7`.
