# DE440

`@zodiacs/engine/de440` places the Sun, the Moon, the planets and the true
node from a sealed pack of Chebyshev series refitted from JPL's DE440. The
root's `withEphemeris` puts such a source in place of astronomy-engine for the
positions the root computes (below). From 1.1.0-rc.8 the package ships the
pack, in `@zodiacs/engine/de440/pack`, so a caller needs nothing but the
package; a caller may still supply a pack of its own. Nothing here fetches
one. zodiacs.org's hosted compute API uses a DE440 source on its server (its
programme unit P4.1).

```ts
import { natalChart, withEphemeris } from "@zodiacs/engine";
import { openShippedDe440Pack } from "@zodiacs/engine/de440/pack";

const source = await openShippedDe440Pack();
const chart = withEphemeris(source, () => natalChart({ utc: "1990-04-15T08:30:00Z", latitude: 51.5, longitude: -0.12 }));
chart.ephemeris; // { name: "jpl-de440", version: "51428874..." }
```

Outside `withEphemeris` nothing changes: `natalChart`, `positions` and the
rest compute with astronomy-engine, as every release has, and a caller who
never imports `@zodiacs/engine/de440/pack` never loads the pack.

With a pack of the caller's own:

```ts
import { readFileSync } from "node:fs";
import { natalChart, withEphemeris } from "@zodiacs/engine";
import { openDe440Pack } from "@zodiacs/engine/de440";

const source = await openDe440Pack(new Uint8Array(readFileSync("de440-1790-2210.v2.zeph")), {
  expectDigest: "51428874d9a47213abc0ff42cbcec65f338624eaa2d8831f0e6ddc3654bf1fa7"
});
const chart = withEphemeris(source, () => natalChart({ utc: "1990-04-15T08:30:00Z", latitude: 51.5, longitude: -0.12 }));
chart.ephemeris; // { name: "jpl-de440", version: "51428874..." }
```

## The pack

A pack is not DE440's own series. The research runtime's compiler 2.0.0
(zodiacs.org's repository, `examples/precision-alpha/tools/compiler/compile.mjs`,
then `tools/seal.mjs`) refits NAIF's `de440.bsp` (SHA-256
`a4ce9bf9b3282becc9f4b2ac3cebe03a2ae7599981aabd7265fd8482fff7c4b5`) body by
body as Chebyshev series on records of its own and stores their coefficients
quantised, each body within an error budget that its header states with the
error the compiler proved for it. Compiled with `--fromYear=1790
--toYear=2210` and sealed, the pack is 2,489,664 bytes with the SHA-256 above
(zodiacs.org's P4.2 record and its Linux rebuild:
[evidence/de440-20261110/README.md](evidence/de440-20261110/README.md)). Its
header gives budgets of 0.01 km for the Moon, 0.3 km for the Sun, the
Earth-Moon barycentre, Mercury and Venus, 0.5 km for Mars and 1 km for Jupiter
to Pluto, and proven position errors of 0.0086 km for the Moon and 0.26 to
0.97 km for the others ([pack-accuracy.json](evidence/de440-20261110/pack-accuracy.json),
`packBodies`).

## The shipped pack

`@zodiacs/engine/de440/pack` carries that pack, byte for byte, in the
package (from 1.1.0-rc.8):

- `DE440_PACK` describes it: its file name, its SHA-256, its 2,489,664 bytes,
  the years it was compiled for (1790 and 2210; its coverage runs from the
  start of 1790 to the start of 2210, TDB) and the kernel's name and SHA-256.
- `de440PackBytes()` gives the bytes, a new `Uint8Array` at each call,
  unchecked.
- `openShippedDe440Pack()` opens them with `openDe440Pack`, expecting
  `DE440_PACK.sha256`, and resolves to the source; later calls give the same
  source. It needs WebCrypto, as `openDe440Pack` does.

A package of JavaScript modules has no portable way to carry a binary file to
every runtime and bundler, so the bytes are base64 text in the entry's own
file, `dist/de440-pack.js`: 3,319,552 characters for the pack, which decode
in memory when a source is first opened. Nothing else in the package imports
that file. `scripts/build-de440-pack.mjs` writes its source,
`src/de440/pack-data.ts`, from the sealed pack and refuses any other bytes;
`scripts/verify-package-contents.mjs` checks that the built file holds the
pack once, with that digest, and that no other entry's graph holds it.

The pack makes the package much larger than 1.1.0-rc.3: 2,696,971 bytes
packed against 331,979, 8.1 times, and 4,477,785 unpacked against
1,142,818, 3.9 times
([evidence/1.1.0-rc.8-20261113/sizes.json](evidence/1.1.0-rc.8-20261113/sizes.json)).
An application that imports the entry carries those 3,319,552 characters in
its bundle, and gzip at its highest level takes them only to 2,357,278 bytes
(Node's zlib; the same file), since the pack's quantised coefficients
compress little; an application that does not import it carries none of
them.

Against an arbiter that is not this engine: at the 240 L1 vectors of the
conformance suite, JPL Horizons's apparent geocentric places from DE441 at 24
TT instants from 1851 to 2148 for the Sun, the Moon and the planets (Mars to
Pluto as barycentres), carried into the IAU 2006/2000A true ecliptic of date,
a chart computed inside `withEphemeris` on the shipped pack is within the
suite's 1″ in longitude and in latitude at all 240. The largest differences
are 0.0127″ in longitude and 0.0011″ in latitude, both the Moon's
(`src/de440-pack.test.ts` enforces all three figures;
`conformance/RESULTS.md`). The arbiter's own check puts the lunar difference
between DE440 and DE441 at up to 12.63 mas in 1851
(`conformance/arbiters/l1/README.md`). The root's own positions, on
astronomy-engine, pass 48 of the 240, with differences up to 18.8″ in
longitude and 19.1″ in latitude (the suite's second section). Those 240
places say nothing of the true node, of speeds, or of instants outside 1851
to 2148.

Whether data refitted from DE440 may be redistributed rests on the owner's
position that DE440 is JPL's public data, not on a statement of JPL's or
NAIF's: NAIF's rules permit redistributing its kernels unmodified and do not
speak of data refitted from one, and the question 1.1.0-rc.3 recorded as put
to NAIF has no answer in this repository (`LICENSING.md`, *DE440 pack*).
Zodiacs.org made the pack; JPL and NAIF have not reviewed or endorsed it.

What the refit costs, measured on that pack by
[tools/pack-accuracy.ts](evidence/de440-20261110/tools/pack-accuracy.ts), the
reduction below on the pack against the same reduction on the raw kernel, at
20,001 instants evenly spaced from 1800 to 2200 TT and either side of every
edge of the pack's records, where a refit errs most: the Moon's place differs
by at most 0.0016″, Venus's by 0.0008″, every other body's by at most
0.0005″; the true node by at most 0.84″, at an edge of the Moon's records
(median 0.0031″ over the evenly spaced instants), because it is formed from
the Moon's velocity, which the refit carries less closely than its position.
At the 200 instants of the ERFA oracles the pack's places are within 0.00094″
and its node within 0.066″ of the chain's. zodiacs.org's tier B checks the pack it
builds against those oracles.

`openDe440Pack(bytes, { expectDigest })` copies the bytes, hashes the whole
file (WebCrypto; without it, a TypeError) and refuses it with `De440Error`
code `digest-mismatch` unless the SHA-256 is `expectDigest`; it then checks
the pack's own trailer against its contents and the header's numbers that it
reads (sizes, offsets, encodings, spans) before reading through it. It
refuses six-byte quantised fields, which the research runtime's reader
decodes wrongly; the pack above has none.

## The reduction

`src/de440/reduce.ts` is the research runtime's reduction with its shipped
options (zodiacs.org's `examples/precision-alpha/src/core/` at site commit
4fa9ffbf), ported operation for operation so that the two give the same
numbers; zodiacs.org's check C9 compares them:

- TT to TDB by the Astronomical Almanac's three-term form;
- light-time by iteration, at most 12 steps, to 1e-11 s;
- deflection of light by the Sun, in ERFA's `eraLd` form, with the Sun at
  reception for the observer's direction and at emission for the source's,
  and a limiter of 1e-14 (none for the Sun itself);
- relativistic annual aberration (`eraAb` without its gravitational term),
  the Earth's velocity from the Chebyshev derivative;
- frame bias and IAU 2006 precession (Fukushima-Williams angles), IAU 2000B
  nutation with the P03 adjustment (the 77 terms, fundamental arguments and
  planetary offsets of `src/nutation.ts`), and the true obliquity, to the
  ecliptic and equinox of date.

The geocentric Moon is MoonRelEMB(t − τ) − EarthRelEMB(t) + [EMB(t − τ) −
EMB(t)], the bracket as −vτ + aτ²/2 from the Earth-Moon barycentre's velocity
and acceleration at t, so that the barycentre's 30 km/s never multiplies the
rounding of the epoch t − τ, as zodiacs.org's preregistration of P4.1 (site
commit 5305fc74) specifies. Mars to Pluto are planetary-system barycentres,
not planet centres.

The true node is the ascending node, on the true ecliptic and equinox of date,
of the plane of r × v, where r and v are the Moon's geometric geocentric
position and velocity in the ICRF from the pack; the South Node is 180° from
it.

On the raw kernel (through the test-only reader `src/de440/kernel.testkit.ts`),
this reduction is within 1e-6″ of the ERFA chain at the oracles' 200 instants,
place and node alike (`src/de440-kernel.test.ts`). That figure is the
reduction's; what the entry gives is that plus the pack's refit, above.

A source refuses an instant outside its pack with `De440Error` code
`out-of-coverage`, not with the RangeError the root gives outside
`EPHEMERIS_SPAN`, and so does an instant whose light-time lookback or speed
samples (±0.001 day for a body, ±0.25 day for the nodes) fall outside it: the
first and last hours of the pack's span are refused for those bodies.

## Within the engine

`withEphemeris(source, fn)` runs `fn`, which must be synchronous and must not
return an iterator, with the root's body positions from `source`:
`positions`, `natalChart` and the functions built on them (transits,
synastry, points, declinations, progressions, returns), the crossing searches
and `moonPhase`. It restores the source before, whatever happens, and calls
nest. The angles and the houses do not depend on the ephemeris and are
computed as before; speeds are the same central differences.

The functions that compute positions from astronomy-engine themselves, or
whose bounds were measured on it, refuse with a TypeError inside
`withEphemeris`, rather than mix two ephemerides or name the wrong one in a
receipt: the calc entry (`calc`, `chart`, `events`), the sky entry's rising,
setting and planetary hours, the vedic entry's star-anchored ayanamsas (and
the sidereal charts on them) and `vargaSensitivity`, and the window entry's
`birthWindow`. The other opt-in entries build on the root's functions and
follow the source.

A chart computed inside names the source in `chart.ephemeris`, and
`createNatalEnvelope` writes the receipt for it: the DE440 conventions set (the
last of `NATAL_RECEIPT_CONVENTION_SETS`), the ephemeris `jpl-de440` with the
pack's SHA-256 as its version, and the required feature
`ephemeris-jpl-de440`, so that an earlier engine refuses the record. A
provenance claim about the ephemeris must then name the same pack.
`createNatalEnvelope` takes `chart.ephemeris` as given, as it takes the rest
of a chart: a chart's data is not authenticated. `natalReplayInput` gives the
chart's input; to recompute a DE440 record, run it inside `withEphemeris` with
a source whose ephemeris version is the receipt's.

## Checks

- `src/de440-pack.test.ts`: the shipped pack's digest and size; the source it
  opens as; the 240 L1 vectors, each within 1″ of Horizons (DE441) through
  `withEphemeris`, and the largest differences above; that the root's own
  positions stay astronomy-engine's; a DE440 receipt naming the shipped pack.
  `scripts/build-de440-pack.test.mjs`: the committed pack text is what the
  generator writes for bytes of that digest.
- `src/de440.test.ts`: a synthetic pack of float64 records, the digest checks,
  the switch, the receipts.
- `src/de440-format.test.ts`: a quantised pack written by an independent
  writer, with every field width the reader accepts, negative values, several
  records per body, a Sun-relative body and the Earth-Moon system, against
  series evaluated in the test; nested sources; the refusals above.
- `src/de440-sources.test.ts`: with a DE440 source, no astronomy-engine
  position function is called in any of the calls zodiacs.org's compute API
  makes.
- `src/de440-kernel.test.ts`, with `PRECISION_KERNEL` set to `de440.bsp`:
  the reduction on the raw kernel against the ERFA chain at 200 instants from
  1800 to 2200 by ten bodies, every place within 1e-6″; the true node within
  1e-6″ of the chain's; and a node with the frame's rotation added to the
  velocity is not the chain's. The chain's outputs were made in zodiacs.org's
  repository and are copied in `docs/evidence/de440-20261110/oracles/`,
  checked by digest.
- `docs/evidence/de440-20261110/pack-accuracy.json`: the pack's own error,
  above, from `tools/pack-accuracy.ts`.
