# DE440

`@zodiacs/engine/de440` places the Sun, the Moon, the planets and the true
node from JPL's DE440, through a sealed pack of its Chebyshev series that the
caller supplies. The root's `withEphemeris` puts such a source in place of
astronomy-engine for every position the engine computes. zodiacs.org's hosted
compute API uses it on its server (its programme unit P4.1); nothing here
fetches a pack or ships one.

```ts
import { readFileSync } from "node:fs";
import { natalChart, withEphemeris } from "@zodiacs/engine";
import { openDe440Pack } from "@zodiacs/engine/de440";

const source = await openDe440Pack(new Uint8Array(readFileSync("de440-1790-2210.v2.zeph")), {
  expectDigest: "51428874d9a47213abc0ff42cbcec65f338624eaa2d8831f0e6ddc3654bf1fa7"
});
const chart = withEphemeris(source, () => natalChart({ utc: "1990-04-15T08:30:00Z", latitude: 51.5, longitude: -0.12 }));
chart.ephemeris; // { name: "jpl-de440", version: "51428874..." }
```

## The pack

A pack is the series of NAIF's `de440.bsp` (SHA-256
`a4ce9bf9b3282becc9f4b2ac3cebe03a2ae7599981aabd7265fd8482fff7c4b5`), compiled
by the research runtime's compiler 2.0.0 (zodiacs.org's repository,
`examples/precision-alpha/tools/compiler/compile.mjs`, then
`tools/seal.mjs`). Compiled with `--fromYear=1790 --toYear=2210` and sealed,
it is 2,489,664 bytes with the SHA-256 above, on macOS (arm64) and on Linux
(x86-64) alike. Whether a pack derived from DE440 may be redistributed is a
question put to NAIF; until it is answered, no pack is distributed, and a
caller compiles one from its own copy of the kernel.

`openDe440Pack(bytes, { expectDigest })` copies the bytes, hashes the whole
file (WebCrypto) and refuses it with `De440Error` code `digest-mismatch`
unless the SHA-256 is `expectDigest`; it then checks the pack's own trailer
against its contents and every number of its header before reading through
it. The source refuses an instant outside its pack (`out-of-coverage`).

## The reduction

`src/de440/reduce.ts` is the research runtime's reduction with its shipped
options, ported operation for operation, so that it gives the runtime's
numbers bit for bit:

- TT to TDB by the Astronomical Almanac's three-term form;
- light-time by iteration, at most 12 steps, to 1e-11 s;
- deflection of light by the Sun, in ERFA's `eraLd` form, with the Sun at
  reception for the observer's direction and at emission for the source's,
  and a limiter of 1e-14 (none for the Sun itself);
- relativistic annual aberration (`eraAb` without its gravitational term),
  the Earth's velocity from the Chebyshev derivative;
- frame bias and IAU 2006 precession (Fukushima-Williams angles), IAU 2000B
  nutation with the P03 adjustment (the 77 terms of `src/nutation.ts`), and
  the true obliquity, to the ecliptic and equinox of date.

The geocentric Moon is MoonRelEMB(t − τ) − EarthRelEMB(t) + [EMB(t − τ) −
EMB(t)], the bracket as −vτ + aτ²/2 from the Earth-Moon barycentre's velocity
and acceleration at t, so that the barycentre's 30 km/s never multiplies the
rounding of the epoch t − τ. Mars to Pluto are planetary-system barycentres,
not planet centres.

The true node is the ascending node, on the true ecliptic and equinox of date,
of the plane of r × v, where r and v are the Moon's geometric geocentric
position and velocity in the ICRF from the pack; the South Node is 180° from
it.

## Within the engine

`withEphemeris(source, fn)` runs `fn`, which must be synchronous, with every
body position from `source`: `positions`, `natalChart` and the functions built
on them, the crossing searches and `moonPhase`. It restores the source before,
whatever happens, and calls nest. The angles and the houses do not depend on
the ephemeris and are computed as before; speeds are the same central
differences.

A chart computed inside names the source in `chart.ephemeris`, and
`createNatalEnvelope` writes the receipt for it: the DE440 conventions set (the
last of `NATAL_RECEIPT_CONVENTION_SETS`), the ephemeris `jpl-de440` with the
pack's SHA-256 as its version, and the required feature
`ephemeris-jpl-de440`, so that an earlier engine refuses the record.

## Checks

- `src/de440.test.ts`: a synthetic pack, the digest checks, the switch, the
  receipts.
- `src/de440-sources.test.ts`: with a DE440 source, no astronomy-engine
  position function is called in any of the calls zodiacs.org's compute API
  makes.
- `src/de440-kernel.test.ts`, with `PRECISION_KERNEL` set to `de440.bsp`:
  the reduction on the raw kernel against an ERFA chain over the same kernel
  (pyerfa, the states in exact arithmetic) at 200 instants from 1800 to 2200
  by ten bodies, every place within 1e-6″; the true node within 1e-6″ of the
  chain's; and a node with the frame's rotation added to the velocity is not
  the chain's. The chain's outputs were made in zodiacs.org's repository and
  are copied in `docs/evidence/de440-20261110/oracles/`, checked by digest.
