# M12 offline setup and isolation

This milestone completes installation and reproduction for the required
bodies. It changes no runtime calculation, frozen source manifest,
coefficient receipt, generator, reference recipe or numerical acceptance
limit. Pholus and Eris remain outside the supported catalogue.

## Installation contract

[SETUP.md](../../SETUP.md) consolidates dependency setup, the complete
original-source inventory, pilot and full-table rebuilds, independent
validation commands and synthetic examples. It distinguishes frozen offline
replay from live capture that may return different bytes. Full loaders
require the original base cache as well as coefficient shards. The repository
contains neither those bulk inputs nor a public download location for their
exact bytes.

`scripts/check-offline.ts` checks installed prerequisites. Its default mode
loads the pilot, verifies the recorded Node runtime and direct npm dependency
versions against the lock, and exercises the pinned independent Python
reducer. Full mode additionally verifies original base, supplemental speed
and final-position responses through the existing strict parsers, checks
coefficient receipts and joins through the offline loader, and verifies
original final-event capture bytes against committed digests. It neither
fetches nor fits; readiness is not a numerical accuracy verdict. Event
reference reconstruction remains a separate command.

`tests/offline-setup.test.ts` exercises missing and corrupted files, dependency
version disagreement, invalid arguments, symlinks, non-file inputs and empty
data. Its native process check disables fetch and runs the pilot preflight
from a different working directory. These are installation tests, not
astronomical accuracy evidence.

`scripts/check-offline-install.mjs` creates a temporary source tree entirely
under this companion's ignored cache. It uses only the existing npm cache
for a fresh locked dependency installation. A module-resolution guard rejects
files outside that tree; a deliberate outside import confirms that guard
before running the example. The pilot coefficient and descriptor bytes must
match the prepared installation exactly. The library example and CLI run
with fetch disabled. The temporary tree is removed on success or failure.
This verifies offline npm installation and runtime reproduction on the
current platform, not Python environment portability or accuracy.

`examples/offline-pilot.ts` demonstrates positions, mixed configured aspects,
generic longitude callbacks, stations, retrograde windows and ingresses. It
retains complete receipts in memory, prints a compact view, and checks
unavailable-body and sample-budget refusals. It uses synthetic instants and
participates in TypeScript checking.

## Notices and isolation

The companion now carries its own MIT text, dependency and inherited-data
licensing record, and attribution notice. They distinguish original code
from JPL data and reused engine material, preserve the parent's unresolved
source-specific terms, and link the installed tools' notices. The runtime
ephemeris dependency retains the parent's exact pin. Nothing was added to
the root package or its licence files.

The scope check verifies bulk/dependency exclusions against Git's actual
ignore rules, rejects tracked files in those paths, and retains file-size,
punctuation and root package exclusion checks. It requires the companion to
remain private and its ephemeris dependency to match the parent. Git commands
only read the index and ignore rules. No archive is created and no build hook
is executed.
