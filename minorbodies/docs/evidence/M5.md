# M5 full-range generation and coverage validation

The registered interval is 1800-01-01 TT inclusive to 2201-01-01 TT
exclusive. Required bodies are Chiron, Ceres, Pallas, Juno and Vesta.
`tests/full-recipe.test.ts` enforces the interval, body set, unchanged pilot
fit settings and exact training/reference epoch sets. This evidence covers
the M5 sampling recipe, not the denser final M11 corpus or event timing.

## Frozen inputs and outputs

`data/manifests/{chiron,ceres,pallas,juno,vesta}.json` records the original
Horizons File API requests through the committed reconstruction recipe,
response digests, retrieval times, complete solution identities and generator
hashes. `full:check` and `tests/full-sources.test.ts` check these records.
`full:build` verifies the complete original source bytes before fitting and
requires the recorded Node runtime and generator implementation.

The generated Cartesian coefficients use only training epochs. Every
held-out epoch, including all reference-speed stencil positions, is excluded
from fitting. `data/receipts/` pins every coefficient shard and its measured
size. The full accuracy suite regenerates these descriptors and requires
exact equality with the receipts. Coefficients, downloads and full reports
stay in ignored directories; the manifests are not a replacement for them.

`full:build` checks position and analytic-velocity continuity at every
segment join, including shard boundaries. `loadFullBody` repeats those
checks, verifies all source and coefficient digests, and refuses epochs
outside installed coverage. The full suite also checks the start, an interior
epoch, the final interior epoch and refusals beyond either edge through that
actual offline loader.

## Independent comparisons

Run from `minorbodies/` with Node 22.22.2 and the frozen original caches:

```sh
npm run full:check
npm run full:build
npm run full:test
```

The active full-data suite passed for every required body on the frozen
datasets. The companion typecheck, default Vitest suite, independent Python
reference tests, retained-fixture verification and package exclusion checks
also passed. The generated coefficient receipts reproduced exactly, including
their byte measurements and all boundary checks.

The explicit full suite compares the complete registered M5 held-out corpus
with original Horizons ICRF vectors, independently reduced by the pinned
ERFA implementation. Its receipt identifies the solution, source manifests,
coefficient digests, reducer dependencies, engine source graph and validation
implementation. `tests/full-accuracy.test.ts` enforces the unchanged limits:

| Quantity | Maximum allowed difference |
| --- | ---: |
| Fitted ICRF direction | 0.05 arcsec |
| Ecliptic longitude | 1 arcsec |
| Ecliptic latitude | 1 arcsec |
| Distance | 1e-7 au |
| Longitude speed | 0.1 arcsec per TT day |
| Latitude speed | 0.1 arcsec per TT day |
| Distance speed | 1e-8 au per TT day |

These are acceptance limits, not measured maxima or physical error bounds.
`src/acceptance.ts` fixes them. Reference-speed convergence must satisfy
one tenth of the corresponding speed budget, as fixed in
`REFERENCE_CONVERGENCE_LIMITS`. Every Cartesian join must also satisfy the
unchanged `FULL_RECIPE.seamLimits`, enforced by the generator and full tests.
Direct and retrograde flags are compared where the independent speed
exceeds the full longitude-speed acceptance allowance.

`full:validate` writes full numerical reports, including failed comparisons,
to `generated/full/<body>/accuracy-report.json`. Missing data or reference
dependencies fail explicitly. Default `npm run check` runs the compact
manifest, parser, mathematical and pilot tests; it does not claim that this
full-data suite ran.

## Retained reference-method failure

The first full-range comparison used the pilot's central differences at
plus/minus 0.005 and 0.01 TT day. Its outcome was:

| Body | Failed gates |
| --- | --- |
| Chiron | Distance-speed agreement and reference distance-speed convergence |
| Ceres | Reference distance-speed convergence |
| Pallas | Reference distance-speed convergence |
| Juno | Reference distance-speed convergence |
| Vesta | Reference distance-speed convergence |

Position, angular-speed and segment-continuity gates passed in that run.
The complete original reports remain in `generated/full-v1-failure/`.
The original measurement algorithm remains in `src/full-validation-v1.ts`.
`npm run full:validate:v1` replays it from the frozen sources and writes to
`generated/full-v1-replay/`, exiting with failure on those gates. This
rejected method is retained for audit and is not the active acceptance run.

Inspection located the largest discrepancies at source request boundaries.
The same discrepancy is present in differences of norms of raw Horizons
vectors, bypassing ERFA and the local evaluator. This supports a reference
numerical effect amplified by very short differences; it does not prove the
internal Horizons mechanism. The failed comparison was not deleted and its
tolerances were not widened.

Before further intake, `SPEED_REFERENCE_RECIPE` registered independent wider
stencils at the same speed centers. Every complete stencil is now inside
one response. The reference derivative is a seven-point centered formula,
with fine/coarse steps of 0.25 and 0.5 TT day. Its exact weights, uniform
actual-epoch requirement, polynomial differentiation, longitude wrapping and
truncation behavior are checked by `tests/reference-derivative.test.ts`.
`tests/speed-reference-sources.test.ts` checks the registered epochs,
training disjointness, intact-stencil batching and frozen manifests.

`data/speed-manifests/` binds the supplemental responses to each body's
original base manifest and identical JPL solution. This corpus is used only
by validation. The original training samples, coefficients, coefficient
receipts, segmentation, degree and all acceptance budgets remain unchanged.
The replacement comparison must pass every original gate; a broader stencil
alone does not establish convergence.

## Limits and package isolation

Finite sampled agreement is not a guarantee at every instant, nor a measure
of the JPL small-body orbit's physical uncertainty. Historical and future
civil-time uncertainty remains separate. Station timing, retrograde windows,
ingresses and the final validation corpus belong to later milestones.

All work is confined to `minorbodies/`. Scope checks enforce file sizes,
documentation punctuation and exclusion from the root npm package. The root
package contents check was attempted but the checkout has no
`dist/calc.d.ts`, so that check cannot complete. No root build, archive
change, version change, publishing or git mutation was performed.
