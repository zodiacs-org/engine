# M6 body adapter verification

The adapter binds loaded minor-body datasets and delegates ordinary bodies
to engine calc without editing the parent package. It retains distinct
provider result types and receipts, adds receipts to structured refusals,
provides generic longitude callbacks, and produces configured-aspect rows
at a common TT epoch. This milestone adds no source capture, fitted
coefficient, accuracy budget or independent event-timing claim.

## Enforcing checks

`tests/body-adapter.test.ts` uses the retained Chiron pilot and direct engine
calls. It checks delegation under supported engine options; unsupported
minor-body conventions; unknown and unloaded bodies; input snapshots;
source and dataset receipts; dates and fractional Julian epochs; coverage
after conversion; common TT aspect speeds; correction-family refusals;
whole-table refusal; and the existing solver's callback and budget behavior.

It also routes the complete registered pilot comparison through the adapter,
using original held-out Horizons samples and the separate ERFA reduction.
Every unchanged arcsecond, distance and speed assertion from
`src/acceptance.ts` is enforced by the adapter test's
`measurePilotAccuracy` comparison. The epoch selection and limited calendar
coverage remain the pilot's, defined in `src/pilot-recipe.ts` and checked in
`tests/pilot-recipe.test.ts`. This repeats the pilot evidence for the new
dispatch path, not an expansion of astronomical coverage or an all-instant
error bound.

Regression tests specifically check that a Delta T pin survives normalized
TT aspect requests, including the engine's inferred-UT1 range refusal;
unknown fields set to undefined cannot disappear before validation; and
overridden Date methods are not used to select an epoch. Malformed
configured-aspect body arrays and nested Date values in ISO fields are also
rejected. Engine and minor-body receipts retain their actual correction
implementations; the aspect helper excludes Moon and lunar-point conventions
that do not match its physical-correction contract.

`tests/full-adapter.test.ts` loads the original ignored full datasets and
checks finite dispatch samples for every required body, including coverage
edges and the final calendar year. Mixed required-body and Mars rows pass
through the existing configured-aspect API. The test also preserves the
engine's narrower coverage refusal. These direct-provider comparisons are
integration checks. `tests/full-accuracy.test.ts` remains the independent
Horizons/ERFA comparison of the registered M5 corpus over the full interval.
Neither suite skips absent datasets or a missing reference reducer.

## Reproduction

From `minorbodies/`, with the recorded Node runtime, local dependencies and
frozen original data installed:

```sh
npm run check
npm run full:test
```

The default check includes typechecking, compact Vitest tests, the independent
Python reducer tests, original source verification and package exclusion.
The full suite additionally requires the ignored full-data caches and
generated shards. Native source-checkout execution uses
`--import ./scripts/register-source.mjs --experimental-strip-types`, as in
the companion README. No root build is needed for these checks.

Verification outcome is recorded in `PLAN.md` after the session's final
checks. The root package completeness check cannot pass in this checkout
because its initial `dist/calc.d.ts` is absent. The separate package exclusion
check reads the npm dry-run file list with scripts disabled and confirms
that `minorbodies/` is excluded. Parent builds, packed files, artifacts and
git metadata remain outside this milestone's changes.
