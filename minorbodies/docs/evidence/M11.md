# M11 final held-out validation

This milestone adds the separate final corpus registered in
[M11-PREREGISTRATION.md](M11-PREREGISTRATION.md). It keeps every fitted
coefficient, training response, interpolation setting and original acceptance
limit unchanged. The earlier M5 coverage tests and calendar-2000 event tests
remain mandatory.

## Actual comparison scope

The position corpus spans 1800-01-01 TT inclusive through 2201-01-01 TT
exclusive for Chiron, Ceres, Pallas, Juno and Vesta. Its final in-range sample
is the end minus 0.000001 TT day. The corpus contains 54,923 explicitly
selected position epochs: deterministic irregular interiors throughout every
segment, exact joins and both sides of every join, and coverage endpoints.
There are 592 independent speed centers, covering selected segments, every
shard join and both coverage endpoints. These are additional to the denser
M5 speed-center corpus, which is still checked.

Complete derivative stencils expand the final source corpus to 60,843 epochs
per body. Positions are also compared at those stencil epochs when inside
coverage, giving 60,833 measured positions per body. Reference-only stencil
support outside coverage is never evaluated by the fitted ephemeris.
`tests/final-recipe.test.ts` enforces the registered counts, epoch selection,
training disjointness and intact-stencil batching.
`tests/full-final-accuracy.test.ts` enforces the complete measured epoch set,
all derivative centers and every segment/shard join. Missing or reordered
rows, nonfinite results and incomplete coefficient coverage fail explicitly.

The new event windows have 365 daily reference centers each and run from
January 1 plus 0.125003 TT day to that epoch plus 364 TT days, in calendar
years 1800, 1900, 2100 and 2200. `tests/final-event-reference.test.ts`
enforces these exact intervals and their placement inside installed coverage.
Daily scans and independent refinements supply station and ingress brackets;
retrograde windows are checked against those stations and independent motion
states. `tests/full-final-events.test.ts` requires nonempty station and ingress
coverage for every required body across these windows, including Chiron.
The earlier M7, M8 and M9 comparisons retain their own calendar-2000 scope.

These are sampled event windows across the supported range, not an exhaustive
event corpus for every year. Daily reference scans can miss a sufficiently
close pair of crossings. Separate invented analytic trajectories test such
pairs; they do not expand the astronomical sample coverage.

## Independent sources and unchanged gates

Only original Horizons positions excluded from fitting supply expectations.
The independent ERFA reducer imports neither this companion's ephemeris nor
the engine's frame functions. It applies IAU 2006/2000A to the already
LT+S-corrected ICRF vectors. Source velocity columns do not supply expected
speeds. Reference rates use position differences with fine/coarse convergence
checks; every stencil remains within a single source response.

`tests/full-final-accuracy.test.ts` enforces each unchanged acceptance limit:

| Quantity | Maximum allowed difference |
| --- | ---: |
| Fitted ICRF direction | 0.05 arcsec |
| Ecliptic longitude | 1 arcsec |
| Ecliptic latitude | 1 arcsec |
| Distance | 1e-7 au |
| Longitude speed | 0.1 arcsec per TT day |
| Latitude speed | 0.1 arcsec per TT day |
| Distance speed | 1e-8 au per TT day |

These are the preregistered acceptance limits in `src/acceptance.ts`, not
measured maxima or physical error bounds. Reference convergence must meet
`REFERENCE_CONVERGENCE_LIMITS`, one tenth of the speed allowances. Every
Cartesian join is checked against the original `FULL_RECIPE.seamLimits`,
including joins between shards. Direct and retrograde states are compared
where independent speed exceeds the original speed allowance.

The event suite repeats the original longitude and longitude-speed gates
through daily scans and station/ingress neighborhoods, with latitude and
distance checks on daily scans and ingress position brackets.
Independent reference brackets must be no wider than 85 seconds, and a
computed event must lie within the bracket or at most 300 seconds outside
it, preserving the M7/M9 gates. The bracket midpoint is not treated as an
exact physical event time. The tests also enforce matching event counts,
directions, window extents and clipping. Search refusals fail the comparison;
the existing synthetic tests enforce refusal behavior and no partial output.

## Reproduction and records

Use Node 22.22.2, the existing locked companion dependencies and the pinned
Python reference environment. From `minorbodies/`, with original caches and
generated coefficient files installed:

```sh
npm run check
npm run full:check
npm run full:test
npm run final:validate
npm run final:events:replay
```

The final tests are part of the explicit full-data configuration, not a
silent skip inside the ordinary offline unit suite. To run them separately:

```sh
npm run full:test -- tests/full-final-accuracy.test.ts
npm run full:test -- tests/full-final-events.test.ts
```

`data/final-manifests/` and `data/final-event-manifests/` bind the exact original
sources and source-generator implementations. Position source captures are in
ignored `.cache/horizons-final/`; event captures are in ignored
`generated/final-events/`, with cached copies under `.cache/horizons-final-events/`.
The coefficient descriptors must still match `data/receipts/` exactly.

`scripts/capture-final.ts` and `scripts/capture-final-events.ts` reconstruct
requests and write proposed manifests only under `generated/`. They run
serially. Fresh live responses may change and cannot restore missing frozen
bytes by assumption. A different solution or source digest requires a new
dataset and evidence, not an in-place replacement of the frozen manifests.

Numerical reports are written under `generated/final/<body>/accuracy-report.json`
and `generated/final-events/<body>/accuracy-report.json`. They retain full
precision, tested epochs/counts, separate maxima, gates, failures, source and
coefficient identities, reducer versions and validation implementation hashes.
Completed failing comparisons are saved before failure exit/test status.
Event intake failures preserve a separate timestamped failure record and
partial captures. Bulk data and reports remain ignored and below the file cap.

## Results and limits

The final position and event suites passed for every required body on the
recorded runtime. The default companion check, frozen base-manifest check and
offline final-event replay also passed. No numerical acceptance gate failed
in the new captures or comparisons, and no reference recipe was revised after
inspection. Full numerical maxima remain in the ignored reports, with the
original limits enforced directly by the committed tests.

An initial combined run of the earlier full-data tests passed its accuracy,
adapter, retrograde and CLI files, then stopped producing output. It was
interrupted; its overall exit status is not recorded as a passing command.
The remaining station and ingress files were checked in separate processes.
This distinction concerns test execution, not a changed numerical allowance.

The next run passed every ingress test, then failed with a Vitest module-loader
timeout before collecting the station file. An isolated station attempt also
timed out while loading astronomy-engine, before any test ran. A fresh isolated
retry passed every station test with the same assertions and timeouts. Every
configured full-data test file has therefore passed, across filtered runs;
the interrupted and failed invocations are retained in the local execution
logs and are not counted as passing aggregate commands. No test, loader
dependency or accuracy allowance was changed to obtain the passing retry.

The root `npm run package:contents` check was attempted and still fails on
the initially absent `dist/calc.d.ts`. The separate companion scope check
passes and confirms exclusion from the root npm package. No root build or
packed-file change was made.

Finite agreement measures interpolation and reduction against the recorded
JPL solution. It does not measure the orbit's physical uncertainty, historical
or future civil-time uncertainty, continuous maximum error or exhaustive event
completeness. Receipt validation status remains separate from this external
evidence; no data receipt is rewritten to imply certified accuracy.

The retained M5 short-stencil reference failure remains documented in
[M5 evidence](M5.md), with its original implementation and replay command.
No original accuracy budget is widened by M11.
