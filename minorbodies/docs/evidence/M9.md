# M9 sign ingress verification

The companion searches tropical sign boundaries through the unchanged engine
longitude solver. It adds direction checks, sign slugs, shared provider-call
budgets and event/search receipts. All changes stay inside `minorbodies/`.
No coefficient recipe, fitted file, training source or original accuracy limit
changes for this milestone.

## Independent reference scope

`src/ingress-reference.ts` defines `INGRESS_REFERENCE_RECIPE` before capture
and comparison with fitted results. Its initial positions come from the
retained original M7 station scan, reduced through the independent Python
ERFA implementation. The reference interval is TT JD 2451544.625003 through
2451909.625003, in synthetic calendar year 2000. The recipe and span are
enforced by `tests/ingress-reference.test.ts`. This is finite event evidence;
it does not establish full-range completeness or physical orbit uncertainty.

The independent scan brackets changes across each sign boundary. Each bracket
is refined by fixed subdivisions using new original Horizons positions, with
no fitted-position or package-event seeding. Reference speed stencils at the
final bracket endpoints come from a separate capture. All requested epochs
pass the existing pilot and full-range training-exclusion gates. The retained
source manifests pin exact requests, original capture digests, solution identity,
recipe, generator source hashes and runtime. The same independent ERFA reducer
handles original scan, refinement and derivative data.

`tests/ingress-reference.test.ts` checks source replay and reference derivative
convergence. `tests/ingress-accuracy.test.ts` checks the Chiron pilot's empty
event scan and original reference positions. `tests/full-ingresses.test.ts`
checks each required full-data body against the reference. Vesta's repeated
direct, retrograde and direct passes through the same boundary are independently
enforced. This real corpus contains no zero-longitude crossing; wraparound and
close station-adjacent pairs are instead checked with analytic functions in
the synthetic suite. They are not additional astronomical reference samples.

`tests/ingress-accuracy-helper.ts` enforces the unchanged longitude limit of
1 arcsecond and longitude-speed limit of 0.1 arcsecond per TT day from
`ACCEPTANCE_POLICY` at the held-out scan and event-neighborhood samples as
applicable. It checks every located event against an independent bracket plus
the existing 300-second timing margin from the station recipe. Reference
brackets must be no wider than 85 seconds and fine/coarse longitude-speed
differences no larger than 0.01 arcsecond per TT day, enforced by the reference
recipe and tests. These are acceptance gates, not measured maxima or physical
uncertainty bounds. No gate was changed after seeing ingress comparisons.

The accuracy helper also splits each query at an independently chosen scan
epoch and checks the subsets against the same reference. Installed coverage
edge calls and refusal at the exclusive end are integration checks. M11 remains
responsible for the final full-range event corpus.

## Synthetic and numerical checks

`tests/ingresses.test.ts` uses independently specified analytic longitude
curves and their derivatives. It checks every sign boundary in either
direction, the wrap between Pisces and Aries, multiple boundaries in time
order, repeated crossings, close pairs near a station and exact touches.
Half-open ownership, fractional TT endpoints, roots rounded near a query
boundary and unsupported terminal direction are exercised separately.

The suite verifies aggregate budget preflight and counts every provider call
across all scans, refinements, classification probes and event positions.
Failure during a later stage discards earlier candidates. It also checks
provider refusals, invalid coordinates and speeds, coverage refusals, original
clock/Delta T records, immutable JSON receipts and no runtime network calls.

Review identified a normalization edge case: the engine solver can round a
tiny nonzero offset to zero when adding a full circle, losing a slow passage.
The wrapper now detects that loss and refuses as `longitude-resolution`.
Both directions have analytic regression tests. Same-side probes alone cannot
establish a touch; only exact boundary longitude and zero speed allow it to be
discarded, and ambiguous cases refuse the entire search.

## Reproduction

From `minorbodies/` on the frozen Node runtime and reference environment
documented in the companion README:

```sh
npm run check
npm run full:test
node --experimental-strip-types scripts/capture-ingress-reference.ts --replay
```

The default suite requires the retained compact sources and independent Python
environment. The full-data suite also requires matching ignored source caches
and coefficient shards; absent files fail rather than skip. Explicit
`--capture` writes proposed reference captures to ignored directories without
replacing retained originals. Full generated reports stay ignored.

The companion check passed, and all full-data test files passed in filtered
runs, including the final strengthened reference-speed sign assertions.
Offline replay verified all ingress sources. A native source-checkout smoke
run exercised the README's Vesta example with runtime fetch disabled and
round-tripped its result through JSON without losing receipts or values.

The session's completed checks are recorded in `PLAN.md`. Root package
exclusion is checked without build hooks. The root package completeness check
requires the initially absent `dist/calc.d.ts`; this task does not create root
build output or change packed files.
