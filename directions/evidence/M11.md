# M11 independent numerical evidence

This milestone expands the analytic evidence for the existing conventions
and repairs unresolved coincidences found during the boundary review.
Every edit is inside `directions/`; the engine package and its build inputs
are unchanged. The starting checkout is `4dd36a7` (M10).

## Reproduce

Use Node 22 with the locked directions tools. From the repository root:

```sh
npm --prefix directions run typecheck
npm --prefix directions test
npm --prefix directions run evidence
npm --prefix directions run check:isolation
```

[report-evidence.mjs](../scripts/report-evidence.mjs) bundles only the
analytic measurement modules into the ignored local build directory. It
writes the source digests, runtime, input fixtures, per-scalar expected and
actual values, signed residuals, allowances, and refusal verdicts under
`directions/generated/m11/`, which is ignored. `summary.json` lists this
run's data files; old unlisted files are not part of the report. Files are
split and checked against the project size limit. The command exits
unsuccessfully if any comparison fails. It performs no chart calculation,
network request, root build or archive packing.

## Numerical fixes and explicit limits

The focused boundary checks found and now guard these false coincidences:

- An IC contact at RAMC `180`, promissor RA `Number.MIN_VALUE`, and zero
  observer latitude and declination previously returned zero. The exact
  westward gap is the positive input RA, even when subtracting it from RAMC
  rounds to the lower-meridian axis. The angle solver now checks the exact
  subtraction residual of the original RA pair at apparent meridian
  contacts and returns `numerical-degeneracy` when equality is lost.
- Projected longitudes `0` and `1e-14` at RAMC `180`, obliquity `23` and
  observer latitude `80` have distinct RAs. Rounded hour angles can both
  become the lower-meridian axis while their semi-arcs remain unequal.
  The zodiacal solver now applies the meridian equality requirement even
  on unequal declination circles. Tests include both observer hemispheres
  and both point orders.
- At zero obliquity and latitude, a sinister square from longitude
  `Number.MIN_VALUE` to a significator at `90` has a positive exact
  residual. Aspect addition previously rounded the ray to `90` and
  asserted zero arc. Compensated ray addition now retains the arithmetic
  residual internally and refuses an apparent coincidence when that
  residual is nonzero. Ordinary rounded sums away from contact and exact
  initial contacts remain accepted.

[m11-angle-numerical.check.ts](../checks/m11-angle-numerical.check.ts) and
[m11-zodiacal-numerical.check.ts](../checks/m11-zodiacal-numerical.check.ts)
derive these arithmetic expectations independently. These cases are
refusal-contract tests, separate from the residual table. The public
result fields and convention choices are unchanged. Near such singular
representations the solver deliberately refuses rather than returning a
new approximate arc; these guards do not resolve every possible floating
point loss.

An exact ecliptic-horizon coincidence remains an explicit limitation:
`phi=-60,epsilon=30,RAMC=90,lambdaS=225,lambdaP=315` can produce rounded
interior coordinates whose transfer lands on a boundary. The separate
test checks its existing `numerical-degeneracy` refusal. Regular arc
coverage does not include that configuration. Geographic and celestial
poles, horizon tangencies, circumpolar directions, converse angles and
zodiacal converse retain their existing refusals. No epsilon snapping or
replacement convention was added.

## Separation from engine integration

The report calls the engine's public pure ecliptic-to-equatorial helper as
part of the tested zodiacal path, but its expected coordinates come from
the independent vector derivations. It does not use engine-computed natal
positions or solar samples as expected values. The references still share
the runtime's elementary functions; they are not an arbitrary precision
validation of those functions.

The existing `natal`, `solar`, `natal-hit`, `natal-scan` and natal CLI
checks remain integration regressions. Their successful comparisons show
that engine coordinates, clock provenance and selected fields survive the
adapters. They do not establish independent ephemeris or directional-arc
accuracy. Complete hit and scan fixtures from M8 and M9 retain their own
independent references. No part of this milestone establishes predictive
validity, a global numerical error bound or a continuous scan theorem.
