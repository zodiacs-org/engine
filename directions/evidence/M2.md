# M2 natal adapter evidence

This milestone adapts synthetic natal inputs through the engine checkout at
`b531d35`. It does not calculate a directional arc or directed age. The
comparisons in [natal.check.ts](../checks/natal.check.ts) are integration
evidence, not independent astronomical accuracy evidence.

## Geometry provenance

The adapter imports only the public root source entry, `../../src/index.js`.
It calls `natalChart` once, then `chartDeclinations` on that chart. It retains
the resulting natal longitudes, latitudes, house cusps and angles without
substitution. Declination rows remain at their full engine latitude; selecting
a later zodiacal projection must not erase these source coordinates.

The engine's `chartDeclinations` obtains true obliquity on the chart's input
scale and delta-T setting. The adapter uses that same obliquity to turn the
engine's MC, with zero ecliptic latitude, into equatorial coordinates through
`eclipticToEquatorial`. Its right ascension is the reported RAMC. This is the
inverse of the MC projection in `computeAngles`, not an independent sidereal
time implementation. Floating-point inversion need not reproduce the original
sidereal angle bit for bit.

The engine's public `calc.houses` exposes its original `armc` for the
integration comparison. Production adaptation does not call it: doing so
would recalculate cusps and introduce that entry's narrower date domain.
The tests fix their RAMC round-trip tolerance before comparing results.

The enforced tolerance is `1e-10` degrees, for floating-point inversion only.
It is checked against public `calc.houses().armc` on these synthetic inputs:

- UTC noon on 1800-06-01, 2000-01-01 and 2199-06-01; latitudes -60 and
  +60 degrees; longitudes -179.999, -120, -30, 60, 150 and 179.999 degrees.
- UT1 noon on 2000-01-01, Julian date 2451545; latitude 35 degrees,
  longitude 20 degrees and pinned delta-T 123.5 seconds.
- UTC noon on 2000-01-01, latitudes -35 and +35 degrees, with longitudes
  selected from the engine's Greenwich ARMC to place RAMC at 0.0000001,
  90, 180, 270 and 359.9999999 degrees.

Every comparison meets that tolerance. No maximum residual was measured or
claimed. This finite input set establishes no physical error bound. Exact
engine-value comparisons separately cover UTC, UT1 and TT with the model and
with a pinned delta-T, the README's synthetic example, engine house-system
selections, and an outside-reference-span flag on a synthetic historical input.

## Input, clock and ownership boundaries

The input explicitly selects known time, time scale, coordinates and natal
house system. Date-only strings are refused, including expanded-year forms;
the adapter does not supply midnight. The engine validates timestamp syntax,
calendar validity, coordinate ranges, delta-T and flag consistency.

Engine clock metadata is retained, including the model or pin, uncertainty,
table identity, UT1 information and leap-second information where present.
`chart.input.utc` and `equatorial.utc` remain input-scale ISO labels. A TT
label is not represented as a conversion to UTC. The snapshot replaces the
engine Date with a string and freezes its own nested arrays and records.
It neither freezes nor keeps a mutable reference to the caller's Date or flags.

The current complete-ecliptic domain requires
`abs(latitude) < 90 - trueObliquity`. Its boundary and both outer regions are
refused, including for natal whole-sign houses, where the engine would not
report a house fallback. This is a project restriction. It does not claim that
all individual contacts outside it are undefined, or that every body inside
it rises and sets. Bodies' own semi-arc domain tests belong to M3.

## Local tooling

All installations and caches are under `directions/`. The project pins the
same `astronomy-engine` dependency version as the root engine; the TypeScript
path mapping and Vitest alias resolve it locally without installing anything
beside the engine source. The adapter's exports are opt-in from `src/natal.ts`;
the pure `src/index.ts` re-exports its types only.

The checkout has no root `dist/`. `npm run package:contents`, with the npm
cache directed into this project, fails its prerequisite assertion:
`packed package is missing dist/calc.d.ts`. Creating an engine build is outside
this task's scope. The local isolation check establishes that npm's dry-run
file list excludes `directions/`; it does not establish the engine's build
completeness, package budgets or archive reproduction.
