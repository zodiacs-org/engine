# M10 CLI evidence

This milestone adds the `directions hit` and `directions scan` commands on
top of the implementation at checkout `70172bd`. It also supplies the pure
natal scan adapter needed for label-only CLI selections. All source,
tooling, tests, examples and documentation remain inside `directions/`.
It introduces no spherical construction or timing convention.

## Numerical references

[cli.check.ts](../checks/cli.check.ts) runs the actual built executable in
separate Node processes against the independently authored
[M8 hit fixtures](hit-examples.ts) and [M9 scan fixtures](scan-examples.ts).
The expected arcs, ages and scan order come from
[M8-derivations.md](M8-derivations.md) and
[M9-derivations.md](M9-derivations.md), with their existing fixture tolerances.
The tests check the returned JSON against those expectations, not against a
previous CLI or library result. They also verify that the primitive geometry
and timing audit survive serialization. This verifies only the stated
synthetic fixtures; it does not establish ephemeris accuracy or predictive
validity.

The executable example [coordinate-hit.json](../examples/coordinate-hit.json)
is a mundane conjunction on the equator with zero declinations. Both
semi-arcs are right angles. At RAMC zero, significator RA 350 gives hour
angle 10, and promissor RA 10 gives hour angle -10. The direct target is
10, so the westward arc is `10 - (-10) = 20` degrees. Ptolemy's unit rate
gives 20 symbolic years. The subprocess test enforces these exact values.
This is hand arithmetic on invented coordinates, not a reconstructed natal
chart. The example
[coordinate-scan.json](../examples/coordinate-scan.json) uses M9's
conjunction and explicit direct/converse choices; its expected arcs are
90 and 270 degrees, derived in M9 and checked with M9's fixture allowance.

[natal-scan.check.ts](../checks/natal-scan.check.ts) separately reuses M8's
body-contact fixtures as supplied synthetic sphere assertions and checks
their independent arcs and ages through the new adapter. Its minimal
snapshots are explicitly not engine-produced charts. They supply no invented
house cusps. For the mundane fixtures, zero obliquity makes the supplied
ecliptic coordinates equal the equatorial coordinates. Zodiacal fixtures
retain their separately stated obliquity and projection.

## Integration and protocol checks

The invented birth inputs in
[natal-hit.json](../examples/natal-hit.json) and
[natal-scan.json](../examples/natal-scan.json) are exercised as integration
examples only. Separate subprocess tests compare complete natal results with
`prepareNatal`, `hitFromNatal` and `scanFromNatal`. Those comparisons establish
engine selection and result preservation, not independent arc accuracy. The
solar tests use explicitly invented arithmetic samples and preserve the
existing `caller-supplied-unverified` epoch association.

The CLI requires a source discriminator, exact envelope fields and an input
path or standard-input marker. The library still validates every calculation
field and returns its original typed refusal. Tests distinguish usage,
file-read, JSON and envelope errors from those calculation refusals. They
check unsupported options, missing fields, unknown bodies, polar geometry,
unsupported converse angles, scan budgets, atomic failure and complete
empty scans. Every example file is run by the subprocess suite.

File and standard-input requests produce the same JSON. Repeated invocations
and recursively reordered object keys produce identical output in the same
build and runtime. The executable is also tested from a working directory
outside the project root. All temporary files remain in the project's
ignored cache and are removed by the tests.

[cli-json.check.ts](../checks/cli-json.check.ts) checks JSON grammar against
`JSON.parse` on finite values and separately rejects duplicate decoded keys
and numeric overflow. It enforces safe own-property handling for
`__proto__`, rejects malformed syntax, and tests container depth at and
beyond the documented limit. The subprocess tests cover invalid UTF-8,
BOM rejection, both byte-limit edges on files and standard input, and
UTF-8 byte counting independent of string length. The constants are
implementation limits enforced by these tests, not measured accuracy bounds.

Closed output pipes are also tested. Write-callback errors determine the
failure status while stream error listeners prevent an unhandled Node stack
trace. A closed stdout returns a JSON error on available stderr; unavailable
stderr exits unsuccessfully without an unhandled exception.

The natal scan adapter uses the existing enumerator with `hitFromNatal` as
its evaluator. Its tests enforce budget checks before any snapshot read,
per-row natal provenance, exact age endpoints, deduplication, stable ordering,
fresh frozen results and caller-owned input preservation. Type checks
require mode-specific branches, explicit converse construction, solar samples
only with the solar key, and label-only selections. The pure import-graph
test still excludes the ephemeris and all process I/O from `src/index.ts`.

## Local build and verification

The CLI bundles relative engine source imports using the project's exact
esbuild dependency and local astronomy-engine dependency. The latter keeps
the engine's existing version. The bundle is ignored under `directions/build/`;
it does not write root `dist/`, change the engine package or create an archive.
The launcher checks the project's Node runtime requirement and uses this
local build. Rebuilding is explicit; it does not detect stale source.

Verification used Node v22.22.2 and the locked local tools on 2026-10-14.
Commands ran from the repository root with that runtime on PATH. npm's
cache was set to `directions/.cache/npm` where the command needed it.

| Command | Result |
| --- | --- |
| `npm --prefix directions run typecheck` | Passed runtime and compile contracts. |
| `npm --prefix directions run build:cli` | Passed; output only in the ignored local build directory. |
| `npm --prefix directions test` | Passed the complete project suite, including CLI subprocess, independent geometry and engine integration checks. |
| `npm --prefix directions run check:isolation` | Passed npm exclusion, project file-size and documentation punctuation checks. |
| `npm run package:contents` | Cannot pass without the existing engine build prerequisite: `packed package is missing dist/calc.d.ts`. |
| `git diff --check` | Passed. |

The initial package-gate attempt could not write npm's default cache; the
retry with the project cache reached the absent engine-build prerequisite.
The package gate is not recorded as passed. Building root `dist/` is outside
this task's authorized scope. The local isolation check verifies exclusion
from npm's dry-run file list without building or packing an archive. All git
writes and draft-PR updates remain the harness's responsibility. M11 and
M12 remain unchecked for later sessions.
