## Native result

The input corpus is unchanged in `src/workloads.ts`: the chart cases are
`whole-utc`, `southern-placidus`, `polar-koch` and `untimed`; houses use its
fixed northern, southern and polar angular inputs across `HOUSE_SYSTEMS`;
the transit scan uses `TRANSIT_CASE`, the synthetic Sun crossing over
`2000-03-01T00:00:00Z` to `2000-04-01T00:00:00Z`. The comparison covers the
complete result trees returned by those cases. No external ephemeris is
used, and these results establish no astronomical accuracy.

Both native target reports were valid, and every workload result repeated
exactly within its own runtime. The first differences from the Node
reference are recorded without rounding:

| Runtime | First original data path | Node binary64 | Runtime binary64 |
| --- | --- | --- | --- |
| Deno | `$["charts"][0]["result"]["bodies"][2]["lat"]` | `bf9a0e65afdb2339` | `bf9a0e65afdb20e9` |
| Bun | `$["charts"][0]["result"]["bodies"][1]["speed"]` | `402afaac235bd1c0` | `402afaac235bf100` |

The source for these values is `m6-runtimes.json`, generated by
`scripts/smoke-runtimes.mjs` through `src/exact.ts`. The Deno and Bun workload
bundles have the same recorded byte digest. Node uses a separate reference
build, and the existing bundle tests compare each target to that reference
when all execute in Node. The native runs establish that numerical outputs
differ on these runtime versions; they do not isolate a particular math
function as the cause. Fields after the first mismatch are not claimed to
match. The native suite remains a failing gate on this tested matrix.

## Runner checks

`tests/runtime-process.check.mjs` exercises actual child processes: complete
stdin/stdout/stderr transport, split UTF-8 and malformed UTF-8, missing tools,
nonzero exit after valid output, signal exit, timeout, combined output byte
limits, already aborted and active aborted runs, and POSIX descendants that
ignore SIGTERM while retaining pipes. The descendant case checks forced
process-group termination. Windows process-tree cleanup was not tested.

`tests/smoke-runtimes.check.mjs` checks default and explicit runtime selection,
executable path handling, malformed and noisy framing, wrong runtime identity
or metadata, malformed exact reports, full exact equality, one-bit changes,
signed zero, Date/string differences, missing properties, failed imports,
nonrepeatable results and timeouts. Its full suite test supplies missing Deno
and Bun executables and requires failure records. Its CLI tests require a
successful Node-only exit, an unsuccessful required-runtime exit, and an
unsuccessful invalid-option exit. Node-only success lists the other runtimes
as unselected. The default unit suite requires only Node; it cannot imply
native Deno or Bun parity.

The new checker builds a fresh reference in memory and executes it through
stdin, avoiding races with the foundation's generated reference file.
The ordinary reference build still writes its local bundle and copied
notices. Every selected native target is freshly built with the existing
graph, file-size and licensing checks. Missing tools and failed processes
cannot produce a passing numerical result. The checker reports errors and
mismatches with a failing exit status and keeps raw exact results in memory.

## Scope

M6 delivers the native checker and records its honest failures. It does not
make the tested Deno or Bun output equal to Node. Engine arithmetic, root
source, packed files, dependencies, root build output and release archives
remain unchanged. Workers and browser execution, performance measurements
and the WASM evaluation remain later milestones. No archive was packed and
no git metadata was changed. Root CI and archive rebuild gates were not run;
the passing edge isolation check does not replace the unavailable root
package-content check.
