# M11 validation

Repository base: `3f71f02`, plus this session's changes under `edge/`.
The [WASM guide](../wasm.md) gives reproducible commands and limitations.
The scripts and retained records below use only the lab's synthetic workloads
and the unchanged engine. No external ephemeris is involved.

## Profile and decision

The final [CPU profile](m11-kernel-profile.json), generated by
`scripts/profile-kernels.mjs`, identified the nutation arithmetic as a candidate
within both chart and transit work. Self samples attributed to nutation were
89 of 912 chart samples and 199 of 868 transit samples; the houses workload
had none. These are sample counts over the record's measurement intervals,
not exact shares of execution time. The ephemeris's `VsopFormula` had more
self samples than nutation in both affected workloads. Houses served as an
unaffected workload control for the experiment.

The [WASM record](m11-wasm-experiment.json), generated by
`scripts/evaluate-wasm.mjs`, contains every paired timing, the compiler and
runtime versions, build and source hashes, startup observations, full workload
inputs, exact-result checks and the acceptance decision. Its runtime is Node
22.23.3, V8 12.4.254.21-node.57, on the recorded Linux x64 shared host. The
reported CPU model string is `Intel(R) Xeon(R) Processor`; this does not identify
a specific processor SKU. It is not a dedicated performance runner.

The acceptance rule was set before the capture: in every round, chart and
transit-scan median duration must improve by at least 10 percent and houses
may regress by at most 10 percent. The evaluator runs 3 rounds, each with
5 warmup batches and 15 retained samples per implementation and workload.
These settings are enforced by `experimentProtocol` and the evidence tests.
Comparisons at the threshold use integer nanoseconds with exact arithmetic.

No chart round met the acceptance threshold. Transit-scan met it in the
second round alone; houses remained within its control limit. The verdict is
`rejected`. WASM remains confined to the explicit experiment build. No timing
was discarded, the threshold was not adjusted, and the existing performance
baseline was not replaced.

The isolated kernel sweep was faster in every measured round. First-round
medians for its complete 64-input sweep were 0.10711346875 ms in JavaScript
and 0.0601222734375 ms in WASM. This micro-kernel observation does not establish
the required end-to-end benefit. The identity control's first-round medians
were 0.00001023653 ms and 0.00001509493 ms per invocation respectively,
including loop and checksum overhead. All rounds appear in the JSON.

AssemblyScript 0.28.9 compiled the 742-byte module in 793814327 ns including
compiler-process startup and file output. Initial observed module construction,
after `WebAssembly.validate`, took 126058 ns. The first instance and table
copy took 651427 ns. Later construction and initialization samples are retained
and explicitly labelled as cache-warmed repeats, not fresh deployment starts.

## Exactness

`verifyKernel` and `tests/wasm.check.mjs` compare all result fields with strict
binary64 equality on 16784 kernel calls. The main grid covers Julian centuries
of TT from -2 to 2 at 4001 evenly spaced inputs with term counts 0, 1, 5 and
77. Supplemental cases exercise all integer term counts from 0 through 77 at
the epochs and signed-zero/subnormal inputs named in the report, including
-20 and 20 centuries. This is a synthetic compatibility corpus, not a claim
over every date or every binary64 value.

Complete chart, houses and transit-scan outputs also matched through the
existing exact transport before and after timing. The report retains their
digest. The kernel's fixed memory remained 65536 bytes; tests also refuse
memory growth and incompatible table layouts. Repeated compilations emitted
identical bytes. Host sine, cosine and remainder remain JS operations; other
runtimes' exactness and WASM performance are unmeasured here.

## Commands and checks

Commands run from the repository root, with Node 22 first on `PATH`:

```sh
npm --prefix edge run typecheck
node --test edge/tests/wasm.check.mjs edge/tests/profile-kernels.check.mjs
node edge/scripts/evaluate-wasm.mjs --machine local-linux-x64 \
  > edge/results/m11-wasm-experiment.json
node edge/scripts/profile-kernels.mjs --machine local-linux-x64 \
  > edge/results/m11-kernel-profile-final.json
EDGE_CHROMIUM_EXECUTABLE=/usr/bin/google-chrome npm --prefix edge test \
  > edge/results/m11-tests.tap 2>&1
npm --prefix edge run check:isolation
npm_config_cache="$PWD/edge/.cache/npm" npm run package:contents
```

The evaluator captured a single complete experiment after the focused tests;
the result was retained without recapturing to improve the verdict. An earlier
profile located the candidate; the final profile was captured after parser
hardening and package changes so its source hashes describe the final profiler.
Profiling and measurement ran serially without other test jobs from this session.

The deterministic tests cover paired timing order,
warmup separation, exact result changes hidden by a checksum, threshold
boundaries and individual workload failures in any round, strict options,
source-digest protection and the compiled kernel itself. The evidence tests
reconstruct every timing summary and the decision from retained samples, and
verify profile totals and matching workload-result identities. They do not
require today's host to reproduce a historical speed.

All implementation, dependency, documentation and evidence changes are under
`edge/`. Root source, package metadata, build output and archives are untouched.
M12 remains for final documentation and CI wiring.
