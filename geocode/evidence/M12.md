M12 completes the implementation plan within `geocode/`. This session adds
an import and offline-operation regression check and records final project
validation. It changes no engine source, atlas data or tools, API declarations,
root configuration, release archive or packed file. The owner's existing
root scope note remains untouched. The harness owns git mutations and the
draft pull request.

## Import and offline-operation review

[check-m12-imports.mjs](check-m12-imports.mjs) and its
[Vitest regression](../tests/imports.test.ts) make the review repeatable.
[m12-imports.json](m12-imports.json) records the runtime and passing checks.
The script uses esbuild from the locked Vitest development dependency tree
to inspect the core graph and prepare temporary ESM bundles in memory.
It disables tree shaking, writes no build output and creates no distributable
artifact. The core graph must reuse the engine geo API and its historical
zone loaders and must exclude chart computation, external packages and the
Node-only atlas, index-loading and HTTP entries. The optional atlas bridge
must reach the existing `atlas/tools/lib.mjs`.

Fresh subprocesses evaluate the bundles with filesystem functions, common
network entry points, subprocess creation, timers and listeners blocked.
Intl access is also blocked during imports, factories, lookup and date-only
queries. Positive controls confirm detection of attempted file reads,
network requests, timers, listeners and Intl access even when the imported
code catches the rejection. The optional HTTP factory and closing before
startup also pass without opening a listener or timer. The probes check
that the library does not change environment variables. Unexpected stdout
or stderr makes the audit fail.

Timed queries then allow Intl while keeping the other guards active. Invented
caller records resolve a modern Kathmandu reading and a historical London
reading through the composed API and preserve the actual provider kind.
These assertions establish offline behavior and delegation; expected offsets
still come from the independent tests referenced in M9.

The [probe](../tests/fixtures/import-audit.mjs) evaluates in-memory data URLs
to exclude TypeScript-loader file reads from application I/O. The atlas's
source file URL is retained when bundling because it derives default paths
from that URL. No atlas data is loaded during this probe. Direct source
loading, real atlas loading, CLI loading and index reads are covered by the
existing integration and subprocess suites. The guard is a Node API
regression check, not an OS network sandbox or a proof against arbitrary
executable providers. It does not inspect every possible JavaScript side
effect. Runtime caches within the reused engine remain part of its existing
implementation.

Source review confirms that time routing delegates to the existing atlas
resolver for matching GeoNames IDs within its civil coverage window, then
to `prepareLocalTime` and `resolveLocalToUtc` elsewhere. Calendar validation
also delegates to the engine. There is no copied atlas rule set, timezone
extract, independent offset arithmetic or chart math. Covered uncertainty
and resolver failures do not trigger tzdb substitution. Source assignments
remain distinct from atlas comparison labels.

## Remaining limitations and root gates

The workbench remains a private TypeScript source-checkout project. Keep its
engine source and atlas siblings available. The committed place sample is
deliberately small, and a downloaded city extract omits other settlements.
Unique means unique in the selected dataset. Index loading and lookup keep
an in-memory snapshot, with no total-memory or throughput claim for arbitrary
dumps. New index generations require explicit loading or service restart.

Modern GeoNames assignments do not establish historical timezone boundaries.
The atlas adapter matches covered source IDs; it cannot route unlisted places
through the atlas's department-based interface because the index lacks that
department field. Outside coverage, older IANA histories have documented
limits and host Intl versions can differ. The Longyearbyen compilation
disagreement recorded in M9 remains explicit. Missing assignments and
unsupported host identifiers remain unavailable without guessed offsets.
Date-only requests yield no instant. Gap/fold policies and atlas uncertainty
remain visible to the consuming application.

The HTTP service's admission limits apply per process and client IP. It has
no authentication, TLS, distributed quota or arbitrary-provider cancellation
layer. Application and proxy privacy controls remain the operator's
responsibility, as [OPERATIONS.md](../OPERATIONS.md) explains. GeoNames and
atlas-derived results retain their separate attribution obligations.

The required root `npm run package:contents` check was attempted with its
output captured in [m12-root-package-check.txt](m12-root-package-check.txt).
It fails because this checkout has no `dist/calc.d.ts`. The task forbids
creating engine `dist/`; no root build was run. The successful exclusion
dry run is not a passing root package budget gate. Root build, export/API
gates, built-engine conformance and archive reconstruction remain unverified
in this session and belong to the repository CI with its normal build.
No package was packed or published, and no git metadata was written.

## Reproduce

From `geocode/`, with the supported Node runtime on PATH and the locked
dependencies installed:

```sh
npm run check
node evidence/check-m12-imports.mjs
node evidence/check-m11-operations.mjs
python3 scripts/select-sample.py --check
python3 scripts/build-time-evidence.py --cc cc --check
node ../atlas/tools/check.mjs
node --test ../atlas/tools/selftest.mjs
```

The timezone command expects its verified source archives to be cached;
first-run acquisition is described in the development guide. Generated data
stays in ignored directories. `git diff --check` and a final scope check
pass after the acceptance documentation and milestone update.
