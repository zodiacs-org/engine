# M6 validation record

This session adds the `geocode lookup` and `geocode tz` source-checkout
commands. They call the existing lookup and composed geocoder, with explicit
local index selection and the existing atlas-first resolution path. They
introduce no time arithmetic, historical rules, place data or chart math.

Results are JSON, with stable exit statuses distinguishing invalid input,
operational failure, no place, unresolved choices and unavailable timezones.
Ambiguity survives result truncation. Date-only requests produce no instant
or offset. Covered atlas uncertainty is preserved, and provider failures do
not silently substitute a timezone answer. Diagnostics do not echo submitted
queries, local paths or raw provider exceptions.

The separate Node-only loader accepts a complete dataset, a builder manifest
or a build directory. It bounds individual file reads, validates records,
checks each listed shard's byte length, digest, count and shared provenance,
and rejects duplicate identifiers. This is consistency checking against the
supplied manifest, not authentication of that manifest or geographic facts.
The entire dataset and lookup index remain in memory. Index directories
must stay static during loading; broader resource and publication hardening
remains in M10.

The executable uses pinned `tsx` through its scoped import API, with disk
caching disabled. Engine and atlas modules are imported from the checkout.
No root build or copied engine/atlas distribution is needed. The private
package declares the `geocode` bin and provides an npm script; direct
`node bin/geocode.mjs` and `npm --silent run geocode -- ...` work from the
source checkout. Installing this folder's dependencies alone does not add
a global command to PATH.

## Checks and reference scope

[cli.test.ts](../tests/cli.test.ts) starts real subprocesses from another
working directory, with a different host timezone and a preload that rejects
Node fetch, HTTP, socket and DNS entry points. The guard is itself exercised;
it is a regression guard, not an operating-system network sandbox. Tests
build the attributed sample locally, with receipts checked, and use invented
queries and civil readings. Temporary data remains under ignored `.tmp/`.

The subprocess checks cover directory, manifest and standalone index inputs,
Unicode and polar-place lookup, exact filters, ambiguity with truncated
suggestions, explicit source IDs, date-only requests, unavailable zones,
syntax validation, help, output streams, exit statuses and private diagnostics.
They compare timed answers with the existing composed resolver for Brest,
New York, Kathmandu, Kolkata, Waitangi and Paris. The cases include atlas
uncertainty, atlas and IANA gaps/folds, half-hour and quarter-hour offsets,
and a request after atlas coverage. A synthetic Intl failure confirms covered
atlas answers do not consult IANA, and a failure outside atlas coverage stays
an error. These comparisons are integration regressions, not independent
historical accuracy evidence. Current civil-only atlas data cannot produce
`no-such-clock` through this command; that exit mapping is reviewed in code.

[load-index.test.ts](../tests/load-index.test.ts) checks immutable snapshots,
real sample-builder output, empty indexes, normalized provenance, malformed
manifests, unsafe shard names, digest/size/count mismatches, mixed provenance,
duplicate IDs, invalid records and UTF-8, missing files, file-size boundaries,
and symlink/directory rejection. The existing independent timezone vector
checks remain part of the full suite, with their sources and limits recorded
in [M4.md](M4.md).

An independent read-only agent review found no substantive M6 defects and
checked the source-checkout launcher and remaining hardening limits. M6 is
the only milestone completed this session; the HTTP server remains next.

## Commands and results

With Node.js v22.22.2 on PATH, from `geocode/`:

```sh
npm ci --ignore-scripts --cache .cache/npm
npm run typecheck
npm test -- --reporter=dot
npm run scope:check
node ../atlas/tools/check.mjs
node --test ../atlas/tools/selftest.mjs
```

[m6-checks.txt](m6-checks.txt) records command-output excerpts and the
validation results. TypeScript passes, all 632 geocode tests pass, and the
atlas data check and its 26 self-tests pass. These counts describe this
session's full geocode suite and unchanged atlas self-test on that runtime.
The scope check verifies candidate sizes, documentation
punctuation and exclusion from the engine npm package with a dry run.

The root `package:contents` check was attempted on the same Node runtime.
It fails because `dist/calc.d.ts` is absent. This task forbids generating
root `dist/`, so this session does not establish the full root package
contents, build, size budgets, export/conformance gates or archive rebuilds.
No release archive was created, no root dependency was installed and no git
metadata was written. The pre-existing untracked `SCOPE-CHANGE.md` remains
untouched.
