# M7 validation record

This session adds an optional Node HTTP transport over the existing geocoder,
with `GET /lookup` and `POST /tz`, and an explicit source-checkout launcher.
The transport delegates lookup and civil-time resolution to the existing
library. It introduces no historical rules, offset arithmetic, place data
or chart calculations. Atlas precedence, citations, uncertainty and native
IANA policy survive JSON serialization.

The service defaults to loopback and an ephemeral port. Construction does
not listen or load files. Startup and shutdown are explicit; shutdown drains
requests and closes remaining connections at its bound. The launcher loads
an explicit offline index and the repository atlas before listening, reports
its bound address, and handles termination signals without logging requests.
Provider code that remains pending cannot be cancelled by the transport.

The HTTP boundary validates routes, methods, selectors, filters, civil dates
and times before calling time providers. It bounds URL, header and body
bytes, including streamed chunked bodies, and rejects compressed or non-UTF-8
JSON. Errors do not echo submitted input, filesystem paths or raw provider
exceptions. Provider RangeErrors stay operational failures. Ordinary library
outcomes, including ambiguous or unavailable answers, retain their complete
result under HTTP 200; callers must inspect the result's statuses.

Per-client rate limiting, overload handling and proxy trust remain the next
milestone, M8. This milestone's service is documented for local use. It adds
no CORS permission, authentication mechanism, remote data acquisition or
request/result persistence. Node's parser and connection deadlines can close
incomplete requests without an application JSON response. Deadline defaults
are configured in code; expired request/header deadline behavior is not
independently measured by this session's tests.

## Checks and reference scope

[http-server.test.ts](../tests/http-server.test.ts) checks the transport with
invented place records, queries and clock readings on ephemeral loopback
ports. It checks structured responses and errors, query normalization,
ambiguity through truncation, explicit place selection, date-only results,
missing zones, the existing IANA gap/fold policy, provider failure privacy,
malformed JSON/UTF-8, byte limits, chunked bodies, malformed HTTP, excessive
headers, client aborts and lifecycle behavior. Shutdown checks cover active
request draining, a pending provider, concurrent startup/close, repeated
close and a busy port.

[http-service.test.ts](../tests/http-service.test.ts) builds the attributed
GeoNames sample locally with pinned receipt checks. It compares HTTP output
to the existing composed resolver for invented Brest, Paris, New York,
Kathmandu, Kolkata and Longyearbyen queries and readings. Covered atlas
answers still work with Intl disabled. Launcher subprocess tests run from
another working directory, check private diagnostics, and exercise both
termination signals. Help is tested with network entry points blocked by
the existing preload guard. That guard is a regression check, not an
operating-system network sandbox.

These are transport and integration regressions, not new geographic or
historical accuracy evidence. Existing independent IANA checks remain in
the full suite; their sources and limitations are in [M4.md](M4.md).
No engine or atlas module is copied, and the pure library entry does not
import the HTTP module or launcher. Full input and generated indexes remain
in ignored directories. The pre-existing untracked `SCOPE-CHANGE.md` remains
untouched.

## Commands and results

Using the cached Node.js v22.22.2 executable under `geocode/.cache/npm` on
PATH, from `geocode/`:

```sh
npm run check
node ../atlas/tools/check.mjs
node --test ../atlas/tools/selftest.mjs
```

[m7-checks.txt](m7-checks.txt) records the full check output, including the
TypeScript check, all 721 passing tests across the full geocode suite, and
the scope check. [m7-atlas-checks.txt](m7-atlas-checks.txt) records the
unchanged atlas's data check and its passing self-tests. The scope check
enforces candidate file sizes, documentation punctuation and exclusion of
`geocode/` from the engine package using an npm dry run.

The root `npm run package:contents` check was attempted on the same runtime;
[m7-package-check.txt](m7-package-check.txt) records its failure because
`dist/calc.d.ts` is absent. The user's scope forbids generating root `dist/`.
This session therefore does not establish the full root build, contents,
size budgets, export/conformance gates or archive rebuilds. No root file,
release archive or git metadata was written. Only M7 is completed here.
