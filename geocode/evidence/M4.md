# M4 validation record

This session added adapters for the existing atlas resolver and engine geo
API. It did not introduce a second timezone database, historical rule set
or time-conversion algorithm. `loadAtlasTimeProvider` explicitly loads the
repository atlas; `createTimeResolver` routes a caller-selected place and
explicit Gregorian date/time to it first. Only GeoNames source IDs establish
atlas place matches. Unmatched records and readings outside the atlas's
local civil coverage use the engine's assigned IANA zone.

Atlas answers preserve the original result, complete cited entries,
uncertainty, fractional offsets, all fold candidates and gap interpretation.
The atlas place's own coordinates remain authoritative for its mean-time
rules. Its timezone label is explicitly a comparison zone, not a historical
boundary assertion. Missing and unsupported IANA assignments return no
offset. Engine answers retain their actual provider metadata and the engine's
earlier-fold/shift-forward-gap policy. The adapter omits the engine longitude
option, so it does not replace tzdb offsets with birthplace mean time.

## Behavioral and independent checks

[atlas-time.test.ts](../tests/atlas-time.test.ts) compares routing and result
preservation directly with the existing atlas resolver for every listed
place. Additional invented requests exercise its civil coverage edges,
uncertain changes, historical gaps/folds, mismatched source labels, missing
or unsupported modern zones, malformed input, provider failures and detached
output. These are integration regressions, not independent validation of
the atlas's historical claims. No atlas data or rules changed.

[iana-time.test.ts](../tests/iana-time.test.ts) reads selected vectors from
the existing [L3 corpus](../../conformance/vectors/L3-time-calendars.json).
Its independent arbiter is `tzdb-2025c-backzone`, described in the
[L3 arbiter record](../../conformance/arbiters/l3/README.md). The selected
IDs are `L3-TZ-0001`, `0002`, `0003`, `0020` through `0026`, `0028` through
`0033`, `0037` through `0040`, and `0043`, all under the `L3-TZ-` prefix.
Only those committed cases are covered by the comparison. Their expected
statuses and offsets come from the independent tzdb build and readers,
not from the engine or a new generated fixture.

The tests cover half-hour and quarter-hour zones, historical DST and IANA
local mean time. They compare the chosen instant where the vector gives
offsets; a nonexistent-time vector supplies only a status, so the chosen
gap instant is checked as a policy regression rather than an independently
verified instant. Separate tests exercise unavailable zones, malformed
requests, early calendar years and the local-to-UTC history-loading seam.
No claim is made about other dates, worldwide geographic completeness or
historical zone boundaries.

[m4-checks.txt](m4-checks.txt) records the runtime and command outputs.
TypeScript, the full geocode Vitest suite and the scope check pass, as do
the existing atlas data check and self-tests. The scope check verifies
candidate file sizes, documentation punctuation and exclusion from the
engine npm package with a dry run.

The builder's emit configuration now names its tools and lookup sources
explicitly, so importing engine source in the library never copies engine
or atlas files into the builder output. The earlier standalone lookup
acceptance script now imports that emitted lookup module directly. Its
existing local-world acceptance check was rerun with the same ignored
snapshot after recompilation:

```sh

npm exec --yes --cache .cache/npm --package=node@22.22.2 -- node evidence/check-m3-lookup.mjs generated/m2-world-validation
```

`dist/calc.d.ts` is absent. Generating root `dist/` is forbidden by this
task. The passing package exclusion check does not establish the root
package's complete contents or size budgets. No root dependencies were
installed, no root build or archive was created, and no git metadata was
written. The pre-existing root `SCOPE-CHANGE.md` remains untouched.

The adapters and their documentation received a separate agent review.
