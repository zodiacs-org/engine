# M9 validation record

This session expands timezone evidence without changing the library, engine
or atlas resolver. The new [test](../tests/time-evidence.test.ts) passes
synthetic place records with explicit zone assignments through the public
time-routing API. Unknown source IDs remain outside atlas coverage, even
when the civil date lies inside its coverage window. No real birth records
or personal queries are involved.

## Independent references and reconstruction

[build-time-evidence.py](../scripts/build-time-evidence.py) reuses the existing
[L3 arbiter](../../conformance/arbiters/l3/build.py) by a read-only import.
It never imports engine code or atlas rules. The compiler inputs, release
digests, per-file digests and compiled tree digest come from the existing
[IANA source receipt](../../conformance/sources/l3/tzdata.json). The pinned
release is tzdb 2025c, in main form with backzone, without leap seconds.

The builder checks the archive and member digests, compiles the pinned
tzcode tools, and requires every compiled timezone byte to match the L3
receipt. Every selected reading must receive the same status, offsets and
abbreviations from tzcode `zdump`, the L3 independent TZif reader and CPython
`zoneinfo.ZoneInfo.from_file`. The Python reader opens explicit compiled
files; it cannot fall back to system timezone files or a Python package.
The [Python zoneinfo documentation](https://docs.python.org/3/library/zoneinfo.html)
documents that file constructor.

The test tooling caches verified release archives in ignored `downloads/`,
uses temporary compiler directories under ignored `.cache/`, and writes
selected references to ignored `generated/m9-time-evidence.json`. Generated
timezone data is not committed. The authored case list and generator are
committed; [m9-checks.txt](m9-checks.txt) records reconstruction, deterministic
rebuilding and test results. The generated reference records source URLs,
digests, reader names, tool versions and the compilation form.

The case list in the generator fixes all local readings before comparison.
It covers London's first DST and wartime double summer time, Lord Howe's
half-hour changes, Kathmandu's quarter-hour legal change, Apia's skipped
date, Sitka's repeated date, Dublin's seconds-bearing offset, Tokyo's old
mean time, polar zone readings in Longyearbyen, McMurdo and Casey, and
ordinary Kolkata and Chatham offsets. Selected transition boundaries are
probed at minute precision; this is not a scan of every transition or date.

For ordinary readings and folds, the expected instants come from the
independent readers. Folds retain the engine's earlier-candidate policy.
For gaps, the independent reference establishes nonexistence and the
transition's before/after offsets. The test separately enforces the engine's
shift-forward policy using those offsets and checks its chosen instant.
Policy agreement does not turn a nonexistent reading into a historical
instant. Source data accuracy and geographic boundary accuracy are not
established by agreement among readers of the same data.

## Recorded polar build difference

For `Arctic/Longyearbyen` at the synthetic reading `1945-06-01T12:00`, the
conformance compilation recipe gives a UTC offset of 10800 seconds, while
the engine's shipped history gives 7200 seconds. These values are enforced
through independently generated reference assertions in the test; the
generator's `polar-link-history` case records both answers. The engine's
chosen instant differs from the conformance recipe and is explicitly
excluded from agreement with that recipe.

The [L3 arbiter record](../../conformance/arbiters/l3/README.md), under
"A link-chain quirk in the 2025c Makefile's backzone build", already names
this identifier among the affected links. The source's backzone Link line
targets `Europe/Oslo`; the recipe's link-chain shortening retains the main
data's `Europe/Berlin` target. The
[engine generator](../../scripts/build-tz-shards.mjs) documents its different
policy: backzone names and links take precedence, without backward links
colliding with backzone zones. The evidence builder obtains the alternate
target directly from the verified backzone source and passes that target
through the same independent readers. The test checks the engine against
that target while also enforcing its disagreement with the conformance
recipe. No expected value is taken from engine output, and neither answer
is presented as historical ground truth for the settlement.

The [IANA theory for the pinned release](https://data.iana.org/time-zones/tzdb-2025c/theory.html)
explains the limitations of older histories and backzone data. This evidence
is about provider and build behavior on selected inputs, not worldwide
historical accuracy.

## Atlas precedence and host availability

The tests read the existing
[atlas differences](../../atlas/tzdb/differences.json) in place. A Brest
mean-time query and a Paris summer-time-end query must retain the atlas's
offset and rule, complete citations and their differing tzdb comparison.
These check routing and provenance against the atlas's committed evidence;
they do not independently establish the historical claims in its rules.
The atlas resolver, rules, comparison extract and API declarations remain
untouched.

A controlled Intl failure simulates a host database lacking a valid IANA
identifier, both before and after the engine's historical-data seam. The
adapter must return `unsupported-timezone` with no guessed instant or
offset, even if shipped historical data exists. Restoring host support
allows an explicit retry. Covered atlas answers bypass host support checks.
Other host failures must propagate. Extra synthetic polar-coordinate inputs
verify that a supplied zone, rather than latitude or longitude, supplies the
offset.

## Commands and results

From `geocode/`, with the cached Node.js v22.22.2 executable on PATH:

```sh
python3 scripts/build-time-evidence.py --cc cc
python3 scripts/build-time-evidence.py --cc cc --check
npm run check
```

Without `--cc`, the builder uses `make zic zdump`; `--make` selects that
executable. The direct compiler option follows the pinned Makefile's tool
source lists and uses isolated timezone-path defaults. Both modes must
match the committed L3 compiled-tree digest, so compiler settings cannot
silently change reference timezone bytes. This environment lacks make;
the direct compiler option was used. The initial downloads came from the
IANA URLs in the receipt; later reconstruction uses cached verified files.

[m9-checks.txt](m9-checks.txt) records typechecking, the complete geocode
Vitest suite, the scope checks and the byte-identical reference rebuild.
The scope check enforces candidate file sizes, documentation punctuation and
exclusion from the engine package by a dry run. Git diff --check also passes.
Root build, archive rebuilds and root package-size gates are outside this
session's scope; the user forbids generating engine dist. No git metadata
was written. Only M9 is completed; index hardening remains M10.
