# M3 validation record

This session added the pure `createPlaceLookup` API over the existing validated
place dataset. It precomputes normalized name and alias entries, matches
city-first text and exact region/country filters, ranks deterministically,
and reports ambiguity before limiting the returned candidates. It preserves
source facts and provenance in frozen snapshots. It adds no timezone math.

[lookup.test.ts](../tests/lookup.test.ts) checks invented datasets and
queries: qualifier interpretations, native-script aliases, Latin accents,
non-Latin vowel marks, punctuation, duplicate names, ranking, input/output
isolation, missing facts and input bounds. The expanded
[sample.test.ts](../tests/sample.test.ts) checks invented lookup requests
against the committed GeoNames sample, including Springfield ambiguity and
polar places. These are behavioral and source-preservation checks, not
measurements of geographic accuracy.

The complete project check ran on Node.js v22.22.2:

```sh
cd geocode
npm exec --yes --cache .cache/npm --package=node@22.22.2 -- npm run check
```

[m3-checks.txt](m3-checks.txt) records the TypeScript, Vitest and scope-check
results. The scope check covers candidate file sizes, documentation punctuation
and exclusion from the root npm package using a dry run.

A separate acceptance check reused the ignored local worldwide build from
the earlier milestone, without a new download:

```sh
cd geocode
npm exec --yes --cache .cache/npm --package=node@22.22.2 -- node node_modules/typescript/bin/tsc -p tsconfig.tools.json
npm exec --yes --cache .cache/npm --package=node@22.22.2 -- node evidence/check-m3-lookup.mjs generated/m2-world-validation
```

[check-m3-lookup.mjs](check-m3-lookup.mjs) verifies each local shard's bytes,
digest, provenance and count, then checks source-ID inclusion and stable
ambiguity/order under truncation. [m3-world-checks.json](m3-world-checks.json)
records its exact manifest hash, runtime and results. The manifest hash
matches the earlier [build record](m2-world-checks.json). This covers only
that local snapshot and the listed synthetic requests, not all GeoNames
data or geographic correctness. The acceptance script is not a hardened
loader for untrusted manifests.

The worldwide check exposed comma-bearing city names and a comma-bearing
country name. Lookup now considers exact whole source labels alongside
structured comma queries, and explicit country/region filters accept the
complete scalar label. Synthetic regressions cover both fixes. Population
and source aliases can produce many plausible matches, which remain
ambiguous even when the first suggestion appears familiar.

The root `npm run package:contents` was also attempted with npm's cache
inside `geocode/`. It fails because `dist/calc.d.ts` is absent, as in the
previous session. Creating the root build is outside this task's allowed
scope. The passing exclusion check does not establish the root package's
complete contents or size budgets. Engine source, packed files, atlas data,
release archives and git metadata were not changed; the existing root
`SCOPE-CHANGE.md` was left untouched.

Index loading, atlas and engine timezone adapters, the CLI and HTTP service
remain later milestones. The search index resides in memory; broad prefixes
enumerate and sort every matching place before truncation. No runtime or
memory performance guarantee is claimed.
