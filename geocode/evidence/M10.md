# M10 validation record

This session hardens local input reading, index consistency and publication.
It changes only the geocode workbench. The existing atlas resolver, atlas
data, engine geo API, timezone sources and committed place sample are reused
without changes. No chart math or historical rules are added.

The builder and acquisition command use sibling staging directories and a
cooperative lock. They rename a completed directory to an absent destination,
after writing its receipt or manifest last. Existing outputs are refused.
Ordinary failures remove owned staging and the lock; an abruptly killed
process leaves them for explicit recovery. The requested index path is never
populated with partial shards.

The loader requires contiguous ordered shard names and exactly the listed
regular files beside the manifest. It verifies bytes, SHA-256, counts,
provenance and duplicate IDs before returning a frozen snapshot. It checks
descriptor identity and file size/timestamps during bounded reads, then
checks the directory and manifest again before returning. The build CLI uses
the same bounded reader for source receipts and validates the downloaded
receipt's schema, license and distinct input roles. Source streams refuse
final-component symlinks and special files and detect size/timestamp changes;
the existing second-pass digests still bind parsing to hashed input bytes.

The GeoNames acquisition reader accepts the expected ZIP member once,
requires a supported ordinary unencrypted member, bounds its declared and
actual uncompressed size, and reads through Python's ZIP integrity checks.
No archive paths are extracted. Complete dumps and generated indexes stay
ignored. Python import caches are also ignored within this project.

## Tests and scope

[build-index.test.ts](../tests/build-index.test.ts) uses manufactured GeoNames
rows to verify staged writes, cleanup after partial shard/manifest writes,
failed rename and explicit retry, cooperating writer exclusion, an output
appearing before publication, source replacement with a symlink, second-pass
source changes, malformed UTF-8 and existing oversized-row/file limits.

[load-index.test.ts](../tests/load-index.test.ts) checks unlisted files,
out-of-order and incomplete shards, truncation, corrupt bytes, mismatched
generation provenance, duplicate IDs, changing manifests and files growing
or shrinking during a read. Successful loads remain immutable and offline.
These are consistency regressions against synthetic local inputs, not
geographic accuracy evidence.

[build-commands.test.ts](../tests/build-commands.test.ts) starts real offline
subprocesses. It kills an index builder after a real staged shard write and
checks that no destination was published and that retry preserves the
abandoned lock. It injects an acquisition write failure and verifies cleanup
and retry. Tiny local ZIP fixtures cover missing and duplicate members,
symlink metadata, NUL-bearing names, encryption flags, unsupported
compression, an oversized declared member, CRC corruption and truncation.
Damaged receipt roles, licenses, UTF-8 and symlinks are refused. No oversized
source file or full dump is created by these failure cases.

Publication assumes a trusted parent and local filesystem rename semantics;
the cooperative lock does not defend against unrelated hostile writers.
There is no fsync or power-loss guarantee. Static published directories are
required, and metadata checks are not a general filesystem transaction or
authentication mechanism. The complete place dataset and lookup index remain
in memory; per-file bounds do not establish a total-memory budget for every
possible dump. Recovery after process death is explicit, as documented in
[README.md](../README.md).

## Commands and results

Run from `geocode/` with Node.js matching this project's package requirements
on PATH. This session used Node.js v22.23.3 and Python 3.13.5, as recorded in
the check output:

```sh
npm run check
python3 scripts/select-sample.py --check
node ../atlas/tools/check.mjs
node --test ../atlas/tools/selftest.mjs
```

[m10-checks.txt](m10-checks.txt) records the completed checks. The full suite
also retains independent IANA evidence and atlas precedence tests from prior
milestones. Its source reconstruction uses cached verified archives when
available. The scope check verifies candidate file sizes, documentation
punctuation and exclusion from the engine package by npm dry run.

Root package build and archive checks are outside this session's allowed
write scope; the checkout has no complete root build. No root dependency,
packed file, release archive or git metadata is changed. The owner's existing
untracked `SCOPE-CHANGE.md` remains untouched. M10 is the only milestone
completed this session.
