# M5 validation record

This session composes the existing offline lookup and atlas-first time
adapters in `createGeocoder`. It adds no timezone math, historical rules or
place data. `getById` shares the lookup's validated place snapshots, so an
explicit selection can address the whole supplied dataset without another
index or a network request.

Text queries with several matches remain unresolved regardless of ranking
or truncation. Callers choose by a separate explicit source-ID request.
Date-only requests preserve the source place and civil date with no time
provider access, default clock reading, UTC instant or offset claim. Timed
requests retain the original atlas or engine result, its provenance and
uncertainty. The engine's UTC Date remains native; result snapshots are
detached so mutations cannot change future answers. Missing assignments
outside atlas coverage remain unavailable, and provider errors propagate.

## Checks and reference scope

[geocoder.test.ts](../tests/geocoder.test.ts) exercises invented datasets,
explicit selection, query filtering, ambiguity before truncation, missing
records and zones, malformed requests, early Gregorian dates, date-only
semantics, provider failures, source precision and detached snapshots.
The test that checks an IANA UTC answer is an integration regression, not
independent timezone accuracy evidence.

[geocoder-atlas.test.ts](../tests/geocoder-atlas.test.ts) builds the committed
attributed GeoNames sample offline and reads the existing atlas directly.
It checks composition for Paris, Brest, Strasbourg and New York; Brest's
March 1891 and Strasbourg's December 1918 uncertainty; New York's November
1883 fold and March/October 1918 gap/fold; and the adjacent local civil
readings at the atlas's coverage boundaries. It also checks missing and
mismatched modern zone labels, coverage ending before the resolved UTC year
ends, date-only provider isolation, covered clock refusals, failure
propagation and a provider that reuses its result object.

These native-resolver comparisons establish preservation and routing,
not independent validation of atlas history. The existing independent IANA
vector checks also pass as part of the full suite; their exact reference
IDs and limits remain in [M4.md](M4.md). No additional accuracy claim or
worldwide completeness claim is made.

The new code and tests received a separate read-only agent review with no
substantive findings. Only M5 was implemented; the CLI is the next unchecked
milestone.

## Commands and results

With Node.js v22.22.2 on PATH, from `geocode/`:

```sh
npm run typecheck
npm test -- --reporter=dot
npm run scope:check
node ../atlas/tools/check.mjs
node --test ../atlas/tools/selftest.mjs
```

[m5-checks.txt](m5-checks.txt) records command-output excerpts. TypeScript
passes, all 495 geocode tests pass, and the atlas data check and its 26
self-tests pass. These counts are for this session's full local suite and
the unchanged atlas self-test on that runtime. The scope check verifies
candidate sizes, documentation punctuation and exclusion from the engine
npm package with a dry run.

From the root, `npm --cache geocode/.cache/npm run package:contents` was
attempted on the same Node runtime. It fails because `dist/calc.d.ts` is
absent. Generating root `dist/` is forbidden by this task, so this session
does not establish the full root package contents, build or size budgets.
No root dependency installation, root build or release archive was created.
No git metadata was written. The pre-existing untracked `SCOPE-CHANGE.md`
remains untouched.
